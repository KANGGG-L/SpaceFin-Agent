# SpaceFin-Agent 演示 · 7 天风险演进剧本（2026-08-01 ~ 2026-08-07）

> 本文档定义校招作品集演示的完整业务剧本：**稳定 → 事件 → 预警 → 处置 → 恢复**。
> 目标是让演示者能沿着一条自洽的叙事线，走完「数据底座 → 估值 → LTV → 预警 → 人工处置 → 闭环」的全链路，
> 并在驾驶舱页面上看到每一天的可见差异。
>
> - 配套验收标准见 `docs/demo/acceptance.md`。
> - **本版已按 2026-08-06 实测灌数结果 + auditor 复核报告（tools/dev/audit_report.md）对齐**；
>   auditor 复核若有新出入，以 auditor 报告为准再微调。
> - 灌数走真实引擎：`tools/risk/main.py --date <业务日> --write-db` 每日批量回填，不改引擎代码。

## 1. 一句话故事线

> 8 月初，全量 5,000 笔贷款风险画像稳定运行（每日预警 107）；8 月 4 日（周二）广州核心区挂牌价异动下探，
> 数据底座反映到抵押物估值，广州贷款 LTV 集体上穿预警线，当日预警跳升至 184；
> 8 月 5 日扩散到峰值 289，风控介入；确认 212 笔、处置 102 笔后，8 月 6 日回落至 209、8 月 7 日企稳收口 147。

**诚实声明（必须在演示与文档中标注）**：

2. **D4 的「广州挂牌价下探」是演示用脚本扰动**（对真实爬取行做单价乘子），不是真实市场信息；
   其目的是演示「数据底座 → 估值 → LTV → 预警」的传导闭环，属于模拟事件场景。
   天河 -12% 为核心冲击场景，增城/万科城等非核心 DWD 键按分阶段加深（D4 -45% → D5 -52% → D7 回升 -40%）、

   与 README 诚实声明口径一致。
3. 事件传导依赖 AVM 重训：扰动后重训模型（r17 → **r20**），广州城市/小区价格编码反映下探后的行情——这是真实引擎行为，不是造假。

## 3. 广州事件设计（D4 触发）

### 3.1 事件内容

- **事件城市 = 广州（gz）**：真实爬取 1,454 条挂牌，叙事为「数据底座真实支撑事件」。
- **触发**：2026-08-04 凌晨，广州挂牌价下探，**核心区按市场冲击场景、非核心 DWD 键按分阶段演示参数加深**（实测分布口径，非代码乘子上限）：

| 区域 | 挂牌价下探幅度（unit_price_yuan 乘子） | 说明 |
|---|---|---|
| 天河核心区 | **-12%**（全程） | 核心冲击场景，满足验收 A2.5（天河实测 -12.0%） |
| 增城 / 万科城等实际命中 DWD 键 | D4 **-45%** → D5 **-52%** → D7 回升 **-40%** | 演示参数加深：AVM 重训对弱扰动响应不足，故逐日加深，传导才可见；不代表真实市场跌幅 |
| 其余非天河区 | D4/D5 **-30%~-42%** → D7 回升 **-25%~-28%** | 演示参数，衬托核心区叙事 |

- **实现方式（data-dev，已执行）**：对 `spacefin_crawler.crawl_housing_sale` 中 `district='gz'` 的行，
  按行所属行政区对 `unit_price_yuan` 应用对应乘子（脚本 UPDATE，可复现、可回滚）。
  gz 抵押物实际命中的 DWD 键是「增城」（区级聚合）与「万科城」（小区级），下探后两键中位单价下降，
  再经 AVM 重训编码到估值。

### 3.2 估值 → LTV → 预警 传导链（真实引擎，无需改代码）

```
crawl_housing_sale 广州挂牌价下探（天河 -12% / 非核心 DWD 键 -45%→-52%→回升 -40%）
  └─▶ DWD 中位单价下降（对走 DWD 回退的抵押物直接生效）
  └─▶ AVM 重训（r17 → r20，广州城市中位/小区目标编码反映新行情）
        └─▶ gz 抵押物 market_valuation 下行（AVM 命中走 AVM，未命中回退 DWD/兜底）
              └─▶ LTV = balance / valuation 上升
                    ├─▶ LTV > 0.75 → warn 预警
                    └─▶ LTV > 0.85 → strong 预警（AC-03）
```

- 引擎优先级：AVM → DWD → true_market_price（`tools/risk/valuation.py`），全链路不用改代码。
- **重训是 D4 事件生效的关键**：AVM 模型只要存在就「命中」（未知小区回退城市中位），
  不重训则估值不变、LTV 不动。实测版本 r17 → r20（多轮重训，最终落库 `2026-08-06-r20`）。
- **低置信抑制**：`spatial_feat_missing_pct > 75` 的贷款不自动预警（AC-04），
  该批数量与合成坐标随机撒点有关，不影响广州事件传导的演示（广州受影响笔数按「非低置信」口径统计）。

## 4. 每日剧本详解（数字为实测）

### D1 · 2026-08-01（周六）· 系统上线

- **叙事**：系统以 5,000 笔贷款规模上线（gz 1,233 笔），全量风险画像生成，离线预警 107 笔（strong 36 / warn 71），盘面平稳。

- **复现动作**：跑引擎 08-02（**不追加房源、不改挂牌价**，保持稳定期逐日一致）。

  （1104 报送实测仅 D5 落库，D3 无报送数据，演示不强调 D3 报送。）

### D4 · 2026-08-04（周二）· 市场异动 ★ 事件日

- **叙事**：广州核心区挂牌价异动下探（天河 -12%；增城/万科城等非核心 DWD 键 **-45%**），数据底座反映，AVM 重训；

- **复现动作**：广州挂牌价下探（3.1 乘子）→ `tools/avm/train.py --out-dir output/avm` 重训 → 跑引擎 08-04。

### D5 · 2026-08-05（周三）· 预警高峰

- **叙事**：异动情绪扩散，非核心 DWD 键进一步加深至 **-52%**，更多广州贷款 LTV 上穿，**全量预警达峰值 289 笔（strong 196）**，
  其中广州 200 笔、**广州 strong 146 笔**；实时流预警 87 笔；风控对 D4 预警启动确认（当日确认 146 笔）。

## 6. 处置节奏设计（实测）

### 6.1 处置状态流转

```
预警产生（ads_ltv_alerts, alert_level=warn/strong）
  └─▶ 人工确认（ads_alert_confirm: loan_id+alert_date+src+confirmed_by）→ 「已确认」
        └─▶ 处置落库（loan.balance 下调 / collateral 上调 / risk_class 人工标记）
              └─▶ 引擎重算（--date 当日）→ LTV 回落 → 当日不再进预警表 → 「已解除」
```

### 6.2 处置闭环实测（截至 D7）

| 指标 | 实测值 |
|---|---|
| 累计确认 | **212 笔**（offline：08-04 确认 66 + 08-05 确认 146） |
| strong 确认率 | **100%**（D4–D5 广州 strong 66+146 全部确认） |
| 累计处置 | **102 笔**（`ads_export_audit` dispose 留痕 219 条，含操作过程） |
| 累计解除 | **100 笔**（处置后重算退出预警） |
| 处置批 LTV 变化 | 重算后均值**下降约 0.50**（追加抵押/提前还款显著改善敞口） |

> 处置类型占比（data-dev 灌数口径）：追加抵押约 50% / 提前还款约 30% / 观察·展期约 20%。

### 6.3 处置动作落库口径（data-dev，已执行）

- **追加抵押**：上调 `collateral.true_market_price`（+15%~+25%，叙事为「补充抵押物/评估复评」）→ 估值上升 → LTV 下降。
- **提前还款**：下调 `loan.balance`（-20%~-30%）→ LTV = balance/valuation 直接下降。
- **观察名单/展期**：`loan.risk_class` 人工改为「关注」并 `ads_export_audit` 留痕（引擎按 LTV 重算覆盖，主要靠确认 + 审计体现）。
- **确认动作**：写 `ads_alert_confirm`（`confirmed_by` 用演示账号如 `risk_officer`）。
