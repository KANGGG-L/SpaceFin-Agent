# P6 策略推演中心 · 自然语言起草规则

> 主要改动：`tools/frontend/pages/p6_policy.py`（nl_parse / decompose 端点）、`tools/frontend/static/pages/p6_policy.js`（NL 入口 + 两阶段确认门 + 回填高亮）。

---

## 1. 目标 workflow

自然语言输入是页面上唯一可见的主输入；拟议规则表单与市场情景块默认**完全不展示**——可选输入也是认知负担，各留一枚 ghost 小按钮按需展开（手动配置规则 / 叠加市场情景，重置收回）。

采用**两阶段确认门**（守门测试 `test_p6_s2_confirm_gate.py`）：

```
① 一句话输入
② 首点「运行推演」→ 只做解析 + 复述（渲染推断说明卡，绝不运行）
③ 核对无误后二次点击 → 才真正运行（推演只读，所见即所跑）
④ 手改输入 / 表单任一处 → 作废草稿、重新裁决闸门
⑤ 解析不出 / 缺作用域 → 展开表单兜底、中止运行，绝不拿默认值静默跑（表单永远兜底）
⑥ （可选、独立步骤）保存生效 —— 现有二次确认 + 审计不变（真正的写门槛）
```

**红线**：NL 有内容时必须解析出作用域才运行；解析失败/缺作用域 → 展开表单 + 中止；规则面板默认完全不展示（仅在 NL 块内保留一枚极轻「手动配置规则」ghost 按钮作专家兜底——网格作用域无法用 NL 表达）；运行/回放/保存/P5 预填自动展开，重置收回。写门槛仍由「保存生效」二次确认承担。非 NL 路径（回放 / P5 预填 / 载入已生效规则）不被确认环节误伤，直接可运行。

## 2. 解析口径：正则骨架 + LLM 填空

解析端点 `POST /api/policy/nl_parse`（`handle_nl_parse`）先跑离线确定性骨架 `_regex_parse_nl`，再由 LLM 主解析补空缺；**正则解析出的值绝对优先**，模型只填空缺/切分冲击子句（`_merge_nl_draft`）。LLM 不可用/失败时静默回退纯正则骨架，功能不崩。

| 要素 | 提取规则 | 缺失时 |
|---|---|---|
| 作用域 | 城市名（CITY_MAP）→ city；行业词（INDUSTRY_MAP）→ industry；两者同现 → 按城市 + 说明改选 | 保持表单现值 |
| LTV 上限 | `(LTV|抵押率)` 后跟数字；带 % 按百分比、>1 视为百分比、≤1 视为小数；区间 [1%, 200%] 外不填入 + 说明 | 保持现值 |
| 惩罚动作 | 关键词：拒贷/拒绝→reject；加严/收紧/严格→strict；提示/预警→notice | 保持现值 |
| 启用/配置理由 | 不由 NL 生成（理由是人对着后果写的治理字段） | 保持现值 |

- **部分成功**：解析出几项回填几项，高亮已填字段，状态行明示缺什么。
- **全部失败**：给出示例句，表单不动。
- **网格作用域**：网格名非自然语言表述（【高危】广州·价格网格…坐标），不支持 NL 指定，继续用表单组合框。解析值不在候选中 → 明示并要求表单选择，不悄悄换值。
- 解析端点只读、**不写审计**（无决策语义：草稿不是动作，运行/保存各有留痕）。

## 3. 交互

- NL 块置于页面最上（最易入口），其后依次为市场情景块（可选叠加）、拟议规则表单（确认面板）。
- 解析成功：字段回填 + 闪烁高亮 + 状态行「已按描述填入：…。请核对后点『运行推演』——不会自动开始。」
- 解析失败：示例句引导，表单不动。

## 4. AI 多步推理与守卫

除 NL 起草外，另设独立端点 `POST /api/policy/decompose`（`handle_decompose`）：把一条粗略想法宏推断为 `rationale` + 1–3 个候选推演条件选项，由 `ai_decompose` + `ai_guard`（0 依赖共享守卫：注入检测 / 逐字段白名单 / 限流分池 / 缓存）承载。配置键与守卫细节见 [ai-decompose-and-anthropic.md](ai-decompose-and-anthropic.md)。

- **软 admin 闸门（restricted 语义）**：非 admin 调 decompose 只拿只读草稿——`inferred` 归 0、推断文案收敛为受限说明、`nl_mode="restricted"`，前端不展示「确认」入口。
- **冲击复验闭环**：模型给出的 `shock_text` 必须经 `_shock_verified` 复验且为**原句子串**；decompose 侧原话没提冲击（`_has_shock_signal`）时模型编的冲击一律剥成纯规则建议——**冲击只能来自原话**。
- **同句混合解析**：`handle_nl_parse` 复用 `parse_scenario` 识别冲击子句，`shock_text` 取子句原文，前端随 admin 闸门预填市场情景块（已有内容不覆盖）。
- **只读纪律**：nl_parse / decompose 均不写审计、不落库；`nl_input` 原文留痕另行评估。
