# 环境依赖参考清单（conda env：`spark`）

> **用途**：本文是 SpaceFin Agent **完整环境依赖的参考清单（reference）**，列出复现开发环境所需的全部组件、版本、获取来源与安装位置。
> **按需接入（Just-in-Time）**：遵循仓库铁律「循序渐进，按需接入」——**不要一次性全装**。下表按「接入时机」分层标注：标「现在·核心」的现在就装（跑通 PoC / 提交规范所需），其余标明了对应阶段（L0/L2/L3），**等真实开发用到该层时再下载**，本文即其获取参考。
> **环境名**：conda env 名统一为 **`spark`**。
> **单一宿主环境**：全仓库宿主侧只用 conda env `spark`（Python 3.10.18）一个环境——ETL / 编排 / 测试 / 宿主渲染服务 / pre-commit 钩子 / PySpark（仅 sedona 演示脚本）都在其中。`tools/orchestrator/.venv` 是指向该环境的**符号链接别名**（脚本默认路径用 `.venv/bin/python` 即可，解析到 spark），**不是独立环境**。采集/ETL 运行依赖清单见 `tools/orchestrator/requirements.txt`（已装入 spark）。
> **宿主事实（Linux）**：conda 为 **Miniforge**，位于 `~/miniforge`，唯一环境 `spark`（Python 3.10.18）；`conda` 不在默认 PATH，操作前先 `conda activate spark` 或 `source ~/miniforge/etc/profile.d/conda.sh`。Node v24 位于 `~/node24/bin`（含 npm/npx），同样不在默认 PATH。Docker 需 `sudo`——当前用户虽在 docker group，但非登录 shell 不会重读组变更，`docker ps` 前先 `newgrp docker` 或直接加 `sudo`。
> **依据**：本仓库 `environment.yml` / `requirements.txt` / `requirements-lite.txt`。

## 2. 方式一：conda 一键建环境（推荐，含现在就装的全部）

前提：本机已装 Miniforge（`conda` 位于 `~/miniforge/bin`，不在默认 PATH，先用 `source ~/miniforge/etc/profile.d/conda.sh` 或 `conda activate spark`）。`environment.yml` 已钉版：python 3.10.18 + openjdk 17 + pyspark 4.2.0 + 爬虫/工具链。

```bash
conda env create -f environment.yml
conda activate spark
python -c "import pyspark; print('pyspark', pyspark.__version__)"   # 期望 4.2.0
java -version                                                      # 期望 17.x
```

> 若 `pyspark==4.2.0` 在 PyPI 尚未发布，把 `environment.yml` 中该行改为 `pyspark` 取最新。
> 本机（Linux 宿主）已装 Miniforge 于 `~/miniforge`，无需重装；若全新机器：`curl -fsSL https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-Linux-x86_64.sh -o miniforge.sh && bash miniforge.sh -b -p $HOME/miniforge`，装后 `source ~/miniforge/etc/profile.d/conda.sh`。

## 6. 提交规范工具链（Node / commitlint）

`environment.yml` 不含 Node。本机（Linux 宿主）已装 **Node v24 于 `~/node24/bin`**（含 npm / npx），项目内 `npm install` 已装入 @commitlint/cli 19.8.1 + config-conventional 19.8.1。

```bash
# ~/node24/bin 不在默认 PATH：每次会话先 export，再执行 npm / npx / pre-commit 相关命令
export PATH=~/node24/bin:$PATH
npm install                     # 安装 @commitlint/cli 19.8.1 + config-conventional 19.8.1
pre-commit install --hook-type commit-msg
```

> **commitlint 钩子依赖 npx**：pre-commit 的 commitlint（以及 eslint / prettier）钩子 `entry` 均为 `npx --no-install ...`，需要 `npx` 在 PATH 上。默认 shell 不带 `~/node24/bin`，**直接 `git commit` 会因找不到 npx 而失败**；提交或手动跑钩子时需加前缀：
> `PATH=~/node24/bin:$PATH git commit ...`（或先 `export PATH`）。

## 9. 常见问题

- **`conda: command not found`**：conda 未在默认 PATH；先 `source ~/miniforge/etc/profile.d/conda.sh` 再 `conda activate spark`（全新机器按第 2 节装 Miniforge）。
- **`pyspark==4.2.0` 找不到**：PyPI 未发布时放宽版本约束为 `pyspark`。
- **PySpark 报找不到 Java**：设 `JAVA_HOME` 指向 Java 17，并确认 `java -version` 为 17.x。
- **`git commit` 报 `npx: command not found` / commitlint 钩子失败**：`~/node24/bin` 不在默认 PATH；提交前 `export PATH=~/node24/bin:$PATH` 或用 `PATH=~/node24/bin:$PATH git commit ...`。
- **`docker: permission denied`**：当前用户若在 docker group 但非登录 shell 不重读组变更；执行 `newgrp docker` 后重试，或直接 `sudo docker ...`。
- **沙箱限速无法建环境**：出网被限流时大文件（Miniforge/PySpark）下载极慢；请在有正常网络的机器执行。
