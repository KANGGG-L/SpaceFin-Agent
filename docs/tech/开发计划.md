# SpaceFin Agent MVP 实际开发计划

> **文档性质**：跨阶段执行计划，把阶段 0–3 的机会/需求/技术结论与阶段 4 评审材料，转化为**可排期、可分配、可验收**的开发路线图。
> **基线**：阶段 3 端到端原型 `mvp_prototype.py` 8/8 验收通过（合成数据、零依赖简化版）；阶段 2/4 技术选型与风险已论证。
> **范围**：本期交付 MVP = L0 湖仓 + L3 AVM + L2 空间 + L5 合规 + LTV 预警 + 1104 报送 + BI 驾驶舱。**不交付** L1 实时反欺诈闭环、L4 多智能体沙盒完整实现（均推迟至 P1）。

## 3. 迭代计划（5 天交付节奏）

> **第一阶段（MVP 开发）总周期 = 5 个日历日**，前提是**全程有 AI 辅助**：需求/代码生成、测试用例编写、文档与评审材料均由 AI 协同产出，且模块级工作高度并行（S1–S4 同日推进），故传统 19 人周 ≈ 4.5 个月的估算被压缩至 5 天。真实排期由研发负责人按资源校准。

| 天 | 阶段目标（原迭代映射） | 关键任务（AI 协同） | 负责角色 | 依赖 | 出口准则 |
|----|----------------------|-------------------|---------|------|---------|
| **D1** | S0 准备/合规 + S1 启动 | 数据授权接洽启动(A-01~03)；环境搭建；湖仓 L0 骨架(Hive+Doris+Multi-Catalog)由 AI 脚手架生成；算法备案启动 | 商务/合规/DE | — | 环境可用；Q1/Q2 已启动且有预计完成时间 |
| **D2** | S1 完成 + S2/S3 并行 | CDC(I-01) 接入；ODS→ADS ETL 落盘；AI 并行生成 AVM(MGWR+GBDT) 与空间(Sedona) 模块初版 | DE/算法/空间 | D1(环境) | ODS 同步达标(TC-01)；分层落盘一致 |
| **D3** | S2/S3 完成 + S4 启动 | AVM+LTV 预警闭环(LTV 红线 0.85 + 推送 I-05)；空间惩罚项生效；1104 G11 模板 + 倒排索引审计(I-04) 生成 | 算法/空间/后端/合规 | D2 | AVM MAPE≤10%(TC-07)；空间 R² 提升≥10pp；1104 口径一致率 100%(TC-08) |
| **D4** | S4 完成 + S5 联调 | 1104 报送 + 合规审计定稿；驾驶舱/预警列表/报送页/RBAC 前端由 AI 生成并前后端联调；降级策略 | 前端/后端/合规 | D3 | 设计验收 D-01～10 通过 |
| **D5** | S6 测试+试点 | AI 生成并执行功能/边界/异常/回归用例；真实数据回归(R-rev-2)；1–2 家试点接入；Go/No-Go | 测试/产品/AI | D4 | 验收清单全绿；上线风险可控；Go |

**总工期**：**5 个日历日**（全程 AI 协同 + 模块并行），相较传统 19 人周 ≈ 4.5 个月压缩约 95%。**Q1/Q2 数据授权为硬前置**——须 D1 即启动并在 D3 前取得实质进展，否则 D5 真实数据回归受阻。

## 4. 任务分解（WBS）

```
S0 准备
  ├─ A-01 试点行数据合规接洽（≥2 家）
  ├─ A-02 AVM 厂商 + 地图 API 授权
  ├─ A-03 Critic 基准口径确认（P1 前置，本期仅记录）
  └─ 研发/测试环境搭建

S1 L0 数据底座
  ├─ Hive 冷存 + Doris 热存部署
  ├─ Multi-Catalog 联邦查询
  ├─ CDC/Binlog 接入（I-01）
  └─ ODS→DWD→DWS→ADS ETL

S2 L3 AVM + LTV
  ├─ MGWR+GBDT 集成（mgwr 库）
  ├─ 月度批次重估任务
  ├─ LTV = 余额/估值 + 红线比对（可配置 0.85）
  └─ 预警推送贷后系统（I-05）

S3 L2 空间
  ├─ Sedona 分布式空间连接
  ├─ 通勤/高危区/POI 图层
  └─ 空间惩罚项配置（US-01）

S4 L5 合规 + 1104
  ├─ Doris 倒排索引审计（I-04）
  ├─ 1104 G11 模板 + 口径一致性校验（R-UBQ-02）
  └─ 特征归因报告（SHAP）

S5 前端 + 联调
  ├─ 资产质量驾驶舱（P2/P3）
  ├─ LTV 预警列表（P8）
  ├─ 1104 报送页（P4）
  ├─ 空间画像页（P5）+ 惩罚项配置页（P6）
  ├─ RBAC 权限（PRD §7.3）
  └─ 降级策略交互（PRD §7.2）

S6 测试 + 试点
  ├─ 功能/边界/异常/回归用例执行（测试用例.md）
  ├─ 真实数据回归（R-rev-2）
  ├─ ≥1–2 家试点行接入
  └─ 版本质量总结 + Go/No-Go
```

## 5. 关键依赖与里程碑

> 时间线以**天**为最小单位（第一阶段总周期 5 天）；以下为依赖关系骨架。D1 启动 S0+S1，D2 起 S1–S4 高度并行，D4 收口前端联调，D5 验收试点。

```
S0 ──┐
     ├─→ S1(L0) ──→ S2(L3+AVM+LTV) ──┐
     │                S3(L2 空间) ────┤
     │                S4(L5 合规) ────┼──→ S5(前端联调) ──→ S6(测试+试点)
     └───────────────────────────────┘
```

| 里程碑 | 节点 | 判定 |
|--------|------|------|
| M0 | S0 结束 | Q1/Q2 授权接洽启动；环境就绪 |
| M1 | S1 结束 | 湖仓分层 + CDC 可用 |
| M2 | S2 结束 | AVM+LTV 预警闭环（MAPE≤10%） |
| M3 | S3 结束 | 空间维度可用，惩罚项生效 |
| M4 | S4 结束 | 1104 报送 + 审计合规 |
| M5 | S5 结束 | 设计验收 D-01～10 通过 |
| M6 | S6 结束 | 验收清单全绿 + 试点上线 + Go |

## 6. 入口 / 出口准则

- **入口准则**：Q1/Q2 已启动接洽（不要求完成，但须有预计时间）；阶段 3 原型 8/8 通过；阶段 4 评审材料已产出。
- **出口准则（MVP 上线）**：
  1. 验收清单（功能/设计/研发/合规）全绿，或仅余 P2/P3 且经产品书面接受；
  2. 上线风险清单无新增 P0（LR-1/LR-2/LR-3 已缓解）；
  3. Q1/Q2 数据授权已落地（真实数据可接入）；
  4. 算法备案前置通过或明确路径（LR-4）；
  5. Go/No-Go = Go。

## 7. 关键风险与缓解

| # | 风险 | 等级 | 缓解（执行动作） |
|---|------|------|----------------|
| R-rev-2 | 真实数据未接入即研发 → schema 返工 | 高 | 合成数据先行开发，真实数据后切换（分环境）；I-01/I-02 契约冻结 |
| R-tech-1 | 技术栈复杂（Doris+Sedona+Flink） | 高 | MVP 先 L0+L3，Flink 仅轻量联动；PoC 已证核心链路 |
| R-tech-2 | MGWR 校准样本不足 | 中 | 限定样本量门槛；无成交小区降级人工 |
| R-cmp-1 | 数据源合规授权不到位 | 高 | Q1/Q2 落实前不接真实数据；白名单 + 授权链路 |
| R-cmp-2 | 算法备案/可解释未达标 | 中 | 倒排索引 + 特征归因报告 + 定期偏见审计 |
| LR-5 | 亿级坐标性能 | 中 | Sedona R-Tree + S2 优化；S3 末压测 |
