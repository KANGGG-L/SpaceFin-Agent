# P6 策略推演中心 · 「组合压力测试」融入「规则试算」统一推演入口

> 把「规则试算」与「组合压力测试」合并为**一张表单、一个「运行推演」按钮**的统一推演入口。
> 主要改动：`tools/frontend/static/pages/p6_policy.js`（前端）；后端沿用既有 `/api/policy/preview` 与 `/api/policy/stress` 端点，无改动。

---

## 1. 背景与目标

P6 原有两个推演入口：「规则试算」（规则必填 + 情景可选）与「组合压力测试」（仅情景、不挂规则），两者本质是同一个 2×2 产品空间的两个象限：

|            | 无情景   | 有情景              |
| ---------- | -------- | ------------------- |
| **无规则** | （拒绝） | 组合压力测试        |
| **有规则** | 规则试算 | 规则 × 情景压力背景 |

**目标**：合并为一张表单、一个「运行推演」按钮；拟议规则与市场情景均为可选，**二者必须至少填其一**。消除模式切换的心智负担，让压力测试复用统一的情景输入（含情景芯片、三语、区级限定词解析等既有能力）。

## 2. 必填矩阵（按角色 × 输入）

| 角色  | 拟议规则      | 市场情景                    | 行为                                                           |
| ----- | ------------- | --------------------------- | -------------------------------------------------------------- |
| 任意  | ✔             | —                           | 规则试算（`/api/policy/preview`）                              |
| admin | ✔             | ✔                           | 规则 × 情景（preview + shock 对比）                            |
| admin | —             | ✔                           | 组合压力测试（`/api/policy/stress`；后端仅接受房价下跌类情景） |
| admin | —             | —（情景文本空）             | 拒绝：「请输入市场情景：仅情景推演不挂规则」                   |
| 任意  | —（无作用域） | （非 admin 情景输入不可见） | 拒绝：「请先选择作用域」                                       |

「至少选其一」由**解析结果驱动的路由**实现（无独立校验项）：解析出市场情景且无作用域 → 走压力测试；否则走规则试算。结构上不会出现双空。

## 3. 交互设计

1. **单一入口**：不再有模式切换控件（原 `p6-mode-bar` / `p6-mode-rule` / `p6-mode-stress` 与 `applyStressMode` 已移除）；历史、对比、校准证据等区恒在各自语义位置，不随模式隐藏。
2. **路由由解析结果决定**：`parseAndFillRule` 解析 NL 时计算局部变量 `route`——`shock_text && st.sbAllowed && scope_value == null` → `"stress"`，否则 `"rule"`（p6_policy.js:5463）；`runSimulation` 读 `st.nlDraft.route` 分支（p6_policy.js:3934）。**路由判断必须先于 `readForm()` 的作用域校验**，否则「仅情景」输入会被误判为缺作用域。
   - 非 admin 的市场情景块整体隐藏（既有 `sbAllowed` 闸门），DA 的必填矩阵自动退化为「规则必填」，RBAC 不变。
3. **情景输入统一**：删除压力测试专用输入框（`p6-stress-hyp`）与专属芯片（`STRESS_SUGGESTIONS`），一律用主情景输入（含情景芯片与建议）。
4. **分组维度零输入（自然语言推断）**：`group_by` 下拉删除，由后端按情景文本自动推断——**维度与冲击范围互补**才有信息量：无限定（全国）→ `city`（哪个城市最危险）；限定地域（城市/区）→ `industry`（该地域内哪个行业最危险；受冲击面已被地域闸门过滤，按城市分组只会得到单行表）。显式传 `group_by` 的 API 调用仍接受（兼容）；响应 `group_by` / `group_note` 回告生效值与推断依据，前端在分组表上方原样展示。
5. **结果区按运行类型显隐**：规则运行 / 历史回放 / 保存回填 → 显示「② 推演结果」卡，隐藏压力结果卡；仅情景运行 → 显示「② 推演结果 · 组合压力」卡（原 `p6-stress-result` 容器），隐藏规则结果卡；重置 → 回规则结果卡空态。实现上直接 toggle `#p6-stress-card` / `#p6-rule-result-card` 的 `display`。
6. **保存保护**：压力结果显示期间「保存生效」禁用。口径由 `syncSaveState` 承担——它只认 `st.preview`，而压力运行不写 `st.preview`，天然锁死；历史只读回放态另加 `_historyReadOnly` 锁。状态与错误统一走主状态行 `sim-status`（无独立压力状态行）。
7. **口径不变（非目标）**：压力测试仍不写审计、不进推演历史/对比/导出（后端既有决策）；利率/收入类情景的仅情景运行仍被后端拒绝（不改 LTV，无组合分布可算）。

## 4. 设计验收点

| # | 验收项                                                              | 判定                          |
| - | ------------------------------------------------------------------- | ----------------------------- |
| A1 | 无模式切换控件，规则与压力共用一张表单、一个按钮                    | 入口唯一                      |
| A2 | 有情景、无作用域 → 走 `/api/policy/stress`                          | 路由由解析结果决定            |
| A3 | 无情景、有作用域 → 走 `/api/policy/preview`                         | 路由由解析结果决定            |
| A4 | 仅情景且情景文本空 → 主状态行报错，不发请求                         | 校验先于请求                  |
| A5 | 压力测试块不触碰 `_history / st.preview / _historyReadOnly`         | 状态隔离                      |
| A6 | 压力结果显示期间「保存生效」禁用；规则运行/回放/保存/重置后恢复      | `syncSaveState` 口径          |
| A7 | 新增文案三语齐备（zh-CN 源 + en + zh-Hant）                         | 字典对账                      |
