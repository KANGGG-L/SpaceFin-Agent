## 0.1 一句话定位

面向互联网金融机构的信贷 / 风控产品与政策决策者，构建一套**风险对冲与策略推演决策支持平台**，解决抵押物估值靠人工、风控结论缺业务共鸣、用户画像被美化偏见污染三类问题，把风控能力从"数据展示"升级为"可推演的策略沙盒"。

- 工作代号：**SpaceFin Agent**
- 产品形态：面向金融机构的风险对冲 / 策略推演决策支持平台（ToB，非放款自动化）

## 0.2 机会描述（Problem Statement）

### 背景与触发

**行业背景。** 2022-2023 年中国房地产市场经历深度调整，部分城市房价下行 15-20%，一批头部开发商出现债务违约。在此期间，一个被忽略的事实浮出水面：大量金融机构的抵押物 LTV（贷款成数）仍停留在放款时的估值上，市场价值变化在风控体系中几乎是"盲区"。据银保监会在 2023 年风险排查中披露，部分银行存续房贷的实际 LTV 已高出账面记录 10-20 个百分点，但系统无法及时预警。

与此同时，互联网金融风控的底层逻辑正从"单一交易数据"向"多模态、时空交织的复杂网络"演进。抵押物的**动态估值**与借款人所处社区的**宏观经济微生态**，已成为决定信贷资产质量的关键变量——但现有体系在三个环节存在系统性断层。

### 思考路径：从观察到命题

```
观察到行业趋势
  ├─ 房产下跌周期暴露 LTV 监控盲区——存量房贷估值实际已背离市场
  ├─ 风控数据源从单一维度向多维度扩展（空间、时序、文本），但未有效融合
  └─ 通用 AI 工具在金融场景中存在"社会期望美化偏见"与"黑箱不可解释"的问题
    ↓
追问：现有方案的局限在哪？
  ├─ 人工估价 → 3-7 天 / 单，无法覆盖 10^4 量级存量贷款
  ├─ 传统风控输出 → 三个干瘪概率（PD/LGD/EAD），业务方无法理解"为什么会违约"
  └─ 通用 LLM 合成画像 → 系统性美化，模拟出来的违约率永远低于实际
    ↓
收敛为三类可验证的具体痛点
```

---

### 三类核心痛点（详细版）

#### P1：抵押物估值依赖人工，频次低、成本高、易被道德风险扭曲

**当前怎么做。** 房产抵押贷款的估值沿袭传统线下模式——评估师实地勘察，结合周边成交案例出具估价报告。每笔耗时 3-7 个工作日，费用 ¥800-1,500 / 次。大多数银行只在**放款时做一次估值**，后续仅在触发特定事件（续贷、展期、不良处置）时才重新评估。

**关键场景：一个 LTV 盲区的形成。**

> 某城商行在 2021 年上半年发放了一批房贷，放款时评估值为 200 万，放款 140 万，LTV = 70%。到 2023 年初，同小区实际成交价已降至 160 万。按真实市值计算，LTV 已升至 87.5%，超过监管红线（一般要求 ≤ 75%）。但银行系统内该笔贷款的估值依然是 200 万，LTV 显示 70%，"一切正常"。如果此时该贷款发生逾期，抵押物处置回收额将远低于预期。这不是个例——该行的房贷组合中，实际 LTV 超过 75% 的笔数可能在账面上被系统性低估。

**量化影响：**

| 维度 | 人工评估现状 | 平台目标 |
|------|-------------|---------|
| 单笔估值成本 | ¥800-1,500 | 近零（自动化） |
| 单笔耗时 | 3-7 天 | 分钟级 |
| 重估频次 | 1 次 / 生命周期 | 可每日/每周批量执行 |
| 覆盖范围 | 仅新增、续贷、不良处置触发 | 全量组合定期扫描 |
| 道德风险 | 评估师倾向高估（为促成业务） | 数据驱动，规则中立 |

**谁感受最深。** 贷后资产保全部门——他们最先发现抵押物不足值的预警滞后；金融机构管理层——他们最不希望看到 LTV 风险在审计中被暴露。

---

#### P2：风控结论缺乏业务共鸣，难以转化为产品与策略决策

**当前怎么做。** 风控团队输出的核心交付物是：PD（违约概率）、LGD（违约损失率）、EAD（违约暴露额）三个数字，按网格 / 客群 / 产品维度汇总。这些数字准确，但**高度抽象**。

**关键场景：策略制定者的"盲人摸象"。**

> 某信贷产品设计师接到任务：设计一款针对"新市民群体"的房贷产品。她去问风控团队："这个群体的画像是什么？还款压力从哪里来？如果利率下调 1%，哪些人会真的改变行为？"风控团队的回答是："目标网格群体的 PD 为 18.4%，LGD 为 42%。"她知道这两个数字，但无法将其转化为产品决策。18.4% 的违约率背后，是多高的债务收入比？房价下跌多少会触发链式违约？她需要的是一个可对话的仿真场景，而不是一个得分。

**量化影响：**

| 维度 | 现状 | 平台目标 |
|------|------|---------|
| 策略假设验证周期 | 2-4 周（跑批测试） | 小时级（沙盒推演） |
| 产品创新试错成本 | 高（开发-测试-上线-发现效果差） | 低（先仿真、再落地） |
| 结论可理解性 | 数字评分，只有风控专家能解析 | 直观的用户行为叙事 |
| 跨部门沟通效率 | 风控与业务之间需反复翻译 | 统一的可视化推演语言 |

**谁感受最深。** 信贷产品设计师——他们需要"为什么"不只是"是什么"；风控政策制定者——他们知道数字准确，但说不清 18% 的违约率背后是什么样的真实人群。

---

#### P3：合成用户画像被美化偏见污染，仿真不可信

**当前怎么做。** 部分机构开始尝试用大语言模型生成典型借款人画像，用于产品测试与策略评估。做法通常是：给定客群统计特征 → 提示 LLM "请描述一位具有以下特征的借款人" → 得到一段人物叙事。

**关键场景：RLHF 的隐性美化效应。**

> 假设输入："月收入 6,000，家庭月支出 4,500（含房租），负债 12 万消费贷，信用卡循环使用率 70%。"
>
> 一位 PM 对 GPT-4 执行这个提示，得到的回复大致如：*"小李是一名在深圳工作的年轻人，虽然收入不高但工作努力，他希望通过合理规划逐步还清债务。虽然目前负债较高，但他对未来抱有积极期望……"*
>
> 这个描述充满了"社会期望偏见"——LLM 在 RLHF 对齐过程中被训练成"乐观、积极、不冒犯"。但不是所有借款人都是积极奋斗的——这位用户的真实风险状态是：收入仅覆盖支出，无储蓄缓冲，任何工作中断都将触发违约链。**乐观画像导致违约低估，低估导致错误的产品设计和定价。**

**量化影响（这个问题比看起来严重得多）：**

| 维度 | 通用 LLM 合成画像 | 平台目标 |
|------|------------------|---------|
| 经济状况表达倾向 | 系统性偏乐观（RLHF 隐含效应） | 如实映射真实分布 |
| 违约率拟合精度 | 严重低估（乐观画像 → 低估违约概率） | 与真实不良率统计同构 |
| 极端场景仿真能力 | 弱（模型回避"负面叙事"） | 支持压力测试与尾部风险分析 |
| 画像多样性与真实性 | 同质性高（趋近平均值） | 还原分布中的真实离散度 |

**谁感受最深。** 风控政策制定者——他们需要真实的画像作为政策制定的基础，而非被美化的版本；合规 / 审计部门——可溯源、可审计的画像比"黑盒生成"更具合规可信度。

---

### 业务目标与价值

- 把风控从"量化呈现"跃升到"认知模拟"：用可交互、可推演的方式，让冰冷数据转化为具象的行为画像。
- 让信贷产品设计师 / 风控政策制定者能在仿真环境中验证复杂商业假设，**低成本、高并发推演**"利率微调 1% 会引发多大违约连锁"等问题。
- 平台价值锚点：不是替代现有风控系统，而是提供现有系统**做不到的战略推演能力**。

## 0.4 核心假设清单（Hypotheses）

> **原则**：每一阶段都围绕"待证伪的命题"展开，而非围绕待实现的功能列表。
> 🔴 生死假设——一旦证伪就推翻或大幅调整方向；🟡 优化假设——影响产品形态但不致命。

| ID | 假设 | 类型 | 证伪意味着 | 验证标准 |
|----|------|------|-----------|---------|
| H1 🔴 | 空间维度特征（社区流转率、区位、配套设施、通勤条件等）对信贷风险 / 抵押物价值有**显著且可量化**的增量解释力 | 生死 | 空间风控的核心价值不成立，应收缩为纯财务数据分析 | 空间回归模型相比纯财务基线，R² 提升 ≥ 10 p.p. |
| H2 🟡 | 精细化空间分析方法相比传统全局统计，能显著提升估值精度与可解释性 | 优化 | 可退化为更简单的统计手段，差异化减弱但产品仍可成立 | 局部模型与全局模型在交叉验证中 MAPE 差异 ≥ 3 p.p. |
| H3 🔴 | 合成行为仿真能够**如实反映**真实经济状态下的不良率分布，而非被美化偏见扭曲 | 生死 | 仿真画像不可用，产品核心能力不成立 | 合成画像的违约率分布与真实数据之间 KS 统计量 ≤ 0.05 |
| H4 🟡 | 金融机构愿意为"策略推演沙盒"能力采纳该平台，并愿接入真实业务数据 | 优化 | 商业化放缓，可先内部 / 试点验证 | 目标机构访谈中 ≥ 60% 表达试用意向 |
| H5 🔴 | 能**合规**获取房产交易、地理区位、业务信贷等基础数据 | 生死 | 数据底座不成立，项目无法启动 | 完成至少 2 家数据源的合规对接评估且结论为可行 |

**验证顺序**：先验 H5（数据是否可得、是否合规）→ 验 H1（空间信息是否真有增量价值）→ 验 H3（仿真是否可信）。

## 0.5 不做清单（Non-goals）

明确列清本产品的"不做什么"，同样重要——它定义了产品的边界，防止范围蔓延。

- ❌ **不做信贷核心交易 / 放款决策自动化**：本平台只做决策支持与预警，不替代最终授信。
- ❌ **不做通用 C 端房产 App / 买房工具**：ToB 金融机构，非 ToC。
- ❌ **不提供法律 / 合规意见**：仅输出风险信号，最终处置由人决策。
- ❌ **不自研通用 LLM 与基础设施**：调用 / 编排现有能力，专注产品逻辑与体验。自研 AVM（空间特征 + 数据闭环定制）属核心能力，阶段 2/3 已论证保留。
- ❌ **不覆盖非房产抵押类全部资产**：聚焦房抵贷 / 大额消费贷场景。
- ❌ **不做实时逐笔反欺诈全能力**：产品重心在"估值 + 行为仿真"，而非全栈反欺诈引擎。

## 0.6 产品思路：需要什么能力，以及为什么

> 本阶段不讨论具体技术选型（那是阶段 2 的工作），只讨论产品需要什么**能力类型**，以及每种能力的选择逻辑。

从三类痛点出发做问题拆解：

| 需要的能力 | 对应痛点 | 能力类型 | 为什么这样分 |
|-----------|---------|---------|-------------|
| 高频自动化估值 | P1 | **模式识别与预测** | 估值本质是"从历史数据中学到规律并外推"，属于数据驱动的预测问题 |
| 风控预警与指标计算 | P1 / P2 | **确定性计算** | LTV、五级分类等有明确监管口径和计算公式，不需要"不确定性生成" |
| 合成行为仿真与策略推演 | P2 / P3 | **复杂场景模拟** | 需要生成多样化的行为叙事、模拟经济压力下的心理反应——确定性规则做不到 |
| 文本检索与回溯 | P3 | **高效索引** | 只需在大量历史结论中快速定位关键文本，不需要理解或生成新内容 |

**四条判断原则**：

1. **问题有确定性答案的 → 用确定性方法解决**。不为了"用 AI"而把可以精确计算的问题模糊化。
2. **问题需要从数据中学规律的 → 应用数据驱动的预测能力**。但不预设具体算法，关键问"这个人值不值得投入"。
3. **问题需要生成多样化叙事的 → 才引入生成与仿真能力**。且必须配套"真实性校验"机制——生成什么不重要，生成得对不对才重要。
4. **问题只需要"找到"的 → 用索引**。成本和可控性都最优，不要为了炫技上大材小用。

> 这一判断框架本身就是产品决策的核心——它回答了"一个 AI 产品经理的判断力在哪里"：不在于"用了什么模型"，而在于**每一段能力的选择都有清晰的理由，且每一段都有对应的质量评估方式**。

---

## 0.7 价值主张

SpaceFin Agent 的竞争力不在于某个具体算法或模型，而在于对以下问题的清晰回答：

- **边界在哪**：什么场景该用什么类型的能力处理，什么场景用 AI 是过度工程
- **如何防范失败**：仿真画像的核心风险是失真——必须建立"生成 → 对照真实分布 → 修正"的自我校准闭环
- **如何建立信任**：平台输出必须可解释、可审计、可溯源——金融机构的决策依赖不建立在"黑盒魔法"上
