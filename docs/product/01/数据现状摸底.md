# 数据现状摸底

> **阶段 1 交付物**：对应阶段 0.8 待办项"数据现状摸底"与生死假设 H5 的验证。
> **状态**：初版完成，基于公开资料与竞品分析中的市场调研数据。**待与目标机构进行数据合规对接评估**。

---

## 1. 背景：SpaceFin Agent 需要哪些数据

从阶段 0 识别的三类痛点和能力拆解来看，SpaceFin Agent 的运行依赖三类基础数据：

| 数据类别 | 用途 | 覆盖范围 | 对项目的影响（若不可获取） |
|---------|------|---------|-------------------------|
| **D1 房产交易数据** | AVM 估值模型训练、实时估价、LTV 监控 | 目标覆盖城市的成交记录、挂牌价、小区基本信息 | H5 生死假设——估值能力不可用 |
| **D2 地理空间数据** | 空间风险推演、社区微生态分析、区位评分 | 地理编码、POI 设施分布、交通/学区/规划信息 | H1 关键假设——空间风控价值不可验证 |
| **D3 信贷业务数据** | 合成画像对齐真实不良率分布、策略沙盒验证 | 产品历史逾期率、LGD、回收率、借款人画像脱敏统计 | H3 关键假设——画像真实性不可校验 |

## 2. D1：房产交易数据

### 2.1 可选数据源

| 数据源 | 数据类型 | 覆盖度 | 获取方式 | 成本 | 合规风险 |
|-------|---------|-------|---------|------|---------|
| **公开房产平台 API** | 成交价、挂牌价、小区均价 | 全国主要城市，贝壳/链家系覆盖最全 | 开放 API（有限频次）或商业授权 | 免费（低频）~ 数万/年（商业） | 低（公开市场数据） |
| **政府不动产登记查询** | 官方成交备案数据 | 视城市而定，部分城市已开放查询 | 政务数据开放平台 / 合作 | 免费或低成本 | 中（需合规用途声明） |
| **第三方 AVM 厂商数据** | 楼盘字典 + 估价模型输出 | 国信达/世联/房讯通覆盖 340+ 城 | API 按次/包年调用 | **1.30-1.80 元/次** 或包年 10-55 万（中原银行 2026 招标价） | 低（已成为银行标准采购流程） |
| **房地产行业报告** | 宏观/城市级别均价指数 | 城市维度，非楼盘级 | 购买或公开下载 | 数千~数万/份 | 低 |

### 2.2 建议策略

**最佳路径**：集成第三方 AVM 厂商的 API 作为底层出值源，不自建房产交易数据库。理由：

1. AVM 厂商已建立数据资产护城河——国信达/世联覆盖 340+ 城、40 万+ 小区、上亿套住房，自建追赶成本高、速度慢
2. 银行采购已有成熟的价格基准（1.30-1.80 元/次），证明此路在成本上可行
3. AVM 厂商的接入已通过银行合规审核，可复用其合规成果

> 此路径已在阶段 1 竞品分析（RICE P0）中确认。

### 2.3 需向目标机构确认的问题

- [ ] 目标机构目前使用哪家 AVM 厂商？合同还剩多久？
- [ ] 机构是否有自建的楼盘数据库？数据质量如何？
- [ ] 机构是否允许将 AVM 数据在系统内二次加工（用于空间风险推演）？
- [ ] 是否存在独家数据源合同限制与其他厂商的集成？

## 3. D2：地理空间数据

### 3.1 可选数据源

| 数据源 | 数据类型 | 覆盖度 | 获取方式 | 成本 | 合规风险 |
|-------|---------|-------|---------|------|---------|
| **高德/百度/腾讯地图 API** | 地理编码、POI、交通、行政区划 | 全国 | 开放 API（有配额限制）或商业授权 | 免费配额或商业版数万/年 | 低 |
| **天地图（国家地理信息平台）** | 行政区划、地理编码 | 全国政务级 | 开放 API | 免费 | 低（政务平台） |
| **公开统计年鉴/人口普查** | 社区级人口统计、经济指标 | 全国，但粒度可能到街道/区 | 统计局官网下载 | 免费 | 低 |
| **房产平台公开数据（安居客）** | 小区配套、学区、交通、周边设施、挂牌样本 | 主要城市 | 爬虫（数据源锁定安居客，合规边界见 §3.3） | 中 | **中高**（投产前法律审查 + 控制访问频次） |
| **商用 GIS 数据服务** | 高精度地理赋码、栅格数据 | 全国 | 商业合作 | 中 | 中（需明确数据使用范围） |

### 3.2 建议策略

**推荐路径**：以开源 / 公共地理数据为免费基础层，商业 API 作为增强层：

- **基础层**（免费）：天地图（行政区划、地理编码）+ 公开统计年鉴（人口、经济指标 at 区/街道级）
- **增强层**（商业）：高德/百度地图 API（POI、交通、路网）+ 商用 GIS 服务（高精度编码）
- **公开采集层**（主渠道）：房产平台公开数据爬虫，**数据源锁定安居客**——是项目房产/空间公开样本的主要获取通道；商业授权接口作为成本与合规的备选增强（合规边界见 §3.3）

### 3.3 合规要点

地理空间数据不涉及个人隐私，合规风险主要来自：
- **爬虫合规**：爬取房产平台公开数据可能违反对方服务条款
- **成果测绘**：对地理信息进行加工后的成果可能涉及测绘资质要求
- **精度限制**：中国对高精度地理数据有保密要求（> 50m 分辨率需资质）

**数据源决策**：公开房产/空间数据**以爬虫获取，数据源锁定安居客**（实现见 `tools/anjuke_crawler/`）。安居客（58 系）TOS 限制批量抓取、绕过其反爬网关存在法律风险——**已知悉并接受**，缓解措施：控制访问频次与规模、代理轮换、仅采公开非 PII 数据、不碰任何个人信息，并在正式投产前完成法律审查。商业授权 API 作为成本/合规的备选增强层保留。

## 4. D3：信贷业务数据

### 4.1 数据特征

信贷业务数据是三类数据中**合规要求最高、获取难度最大**的一类：

| 数据子类 | 特征 | 敏感性 | 合规要求 |
|---------|------|-------|---------|
| 逾期率/违约率（客群维度脱敏） | 聚合统计，具体到网格/客群 | **中等**（不含个人身份信息） | 匿名化后可分享 |
| LGD/EAD/回收率 | 产品级聚合统计 | 低（产品级数据） | 可在数据使用协议中约定 |
| 借款人画像（个体级） | 含收入、职业、负债等个人数据 | **极高** | 触发个保法；原则上不能出机构 |
| 不良贷款明细 | 含个人身份 + 贷款信息 | **极高** | 触发个保法、征信业务管理要求 |

### 4.2 合规红线

根据《个人信息保护法》《数据安全法》及征信业务管理要求：

- **个保法红线**：个人金融信息原则上**不能离开机构内部网络**进行处理
- **征信业务红线**：涉及个人信用评分 / 信贷决策的工具须持牌（百行/朴道等征信机构）
- **数据安全红线**：信贷数据与房产/空间数据的融合需要严格的数据分类分级管理

> 公开案例（冰鉴）表明：无征信牌照的厂商只能做模型，不能直连金融机构核心业务数据，须经持牌征信机构转售。

### 4.3 建议策略

**推荐数据获取路径（按合规风险从低到高）**：

| 路径 | 做法 | 合规风险 | 可用数据 |
|------|------|---------|---------|
| **① 合成数据验证** | 用公开统计分布 + 蒙特卡洛模拟生成符合真实分布特征的合成数据 | 无（完全不碰真实数据） | 可验证建模流程，但无法证明精度 |
| **② 机构内部署** | 将 SpaceFin Agent 部署在机构内部网络，数据不出域 | 低（符合个保法） | 可接全量数据，但受限于机构 IT 环境 |
| **③ 脱敏后导出** | 机构对数据进行匿名化/聚合处理后导出 | 中（需数据使用协议） | 聚合统计（客群级），无法做个体级 |
| **④ 经征信机构对接** | 通过百行/朴道等持牌征信机构获取脱敏数据 | 中低（走持牌通道） | 取决于征信机构的接口能力 |
| **⑤ 直接拉取个人数据** | —— | **极高，不可行** | 应主动规避 |

### 4.4 推荐路线

**第一阶段（Phase 0-1，PoC 验证期）**：
- 用公开统计分布 + 合成数据验证模型流程（路径 ①）
- 地理空间数据使用公共 + 商业 API（D2 方案）
- 房产 AVM 使用第三方厂商 API 集成（D1 方案）

**第二阶段（Phase 2-3，试点期）**：
- 选择 1-2 家合作机构走路径 ②（机构内部署）或 ③（脱敏导出）
- 验证空间风险推演是否与真实不良率有显著相关性（H1）
- 验证合成画像是否与真实不良率分布同构（H3）

## 5. 整体评估：H5 验证结论

| 验证维度 | 结论 | 信心 | 关键风险 |
|---------|------|------|---------|
| **房产交易数据**（D1） | **可得且合规**：通过集成第三方 AVM 厂商 API 实现 | 高 | 需确认目标机构是否已有 AVM 供应商 |
| **地理空间数据**（D2） | **可得**：公共 API + 安居客爬虫（锁定数据源）组合方案 | 高 | 爬虫合规风险已知悉并接受（投产前法律审查）；高精度地理数据有资质要求 |
| **信贷业务数据**（D3 个体级） | **不可直接获取**：个保法红线，需走机构内部署或持牌通道 | 中 | 这是最大风险点——能否说服机构接受部署模式 |
| **信贷业务数据**（D3 聚合级） | **可得且合规**：脱敏聚合统计可基于数据使用协议分享 | 中高 | 聚合粒度过粗可能影响画像对齐精度 |

**H5 综合判定**：🟡 **有可行路径但有条件**。房产与地理数据可行，信贷业务数据的获取取决于合作机构是否接受内部署模式。建议在启动阶段 2 前完成至少 1 家目标机构的数据合规初步接洽。
