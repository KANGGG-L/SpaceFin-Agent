## 2. 用户画像（Persona Cards）

### 2.1 王敏 · 信贷产品设计师（主用户）

| 维度 | 描述 |
|------|------|
| **基本信息** | 32 岁，互联网银行信贷产品线产品经理，从业 5 年。经管 / 金融背景，编程能力有限（懂 SQL 查询）。 |
| **日常职责** | 负责信贷产品的市场调研、方案设计、上线跟踪与迭代。每月设计 1-2 款新产品方案，管理 3-5 个存量产品优化。 |
| **核心工作流** | 收集用户需求 → 与风控确认风险边界 → 设计产品参数（利率/期限/额度）→ 推动 IT 开发 → 上线后跟踪逾期率 → 迭代 |
| **当前最大痛点** | **接不到风控的"人话"**。风控团队只给 PD/LGD/EAD 三个数字，她无法理解"这个群体到底长什么样"，也就无法判断产品参数是否合理。一次策略假设验证周期 2-4 周，试错成本极高。 |
| **日常使用工具** | Excel（表格建模）、内部报表系统（查看逾期率）、飞书/钉钉审批流 |
| **对 SpaceFin 的核心期望** | 输入产品参数（利率、额度上限），沙盒就能自动推演违约响应曲线，并生成可视化的借款人群体画像。"我不需要知道模型怎么算的，我要知道结果长得像什么。" |
| **采纳门槛** | 沙盒推演结果与真实上线后回收数据的偏差需在可接受范围内（偏差 < 20%）；操作无需代码；单次推演耗时不超过 1 小时。 |
| **典型使用场景** | "利率下调 1.5% 会影响多少新增借款人？新增客户中违约率会上升多少？" → 输入参数 → 沙盒 30 分钟给出推演结果 + 受影响群体的合成画像分布。 |

### 2.2 陈磊 · 风控政策制定者（主用户）

| 维度 | 描述 |
|------|------|
| **基本信息** | 38 岁，风控总监 / 高级风控经理，从业 10+ 年。统计学 / 金融工程背景，熟悉评分卡与模型。 |
| **日常职责** | 制定信贷审批政策、设定风险容忍度、监测组合风险、向监管报送风险数据。管理 5-10 人的风控团队。 |
| **核心工作流** | 分析历史数据 → 确定风险分档 → 制定授信规则 → 与产品/业务对齐 → 上线监控 → 按季度复盘调整 |
| **当前最大痛点** | **干瘪分数缺乏业务共鸣**。他能算出"某网格违约率 18.4%"，但给业务部门讲不通，跨部门沟通需要反复翻译。他需要一个更直观的方式向外输出风险洞察。另一方面，合成用户生成工具普遍不靠谱——LLM 生成的人物描述太乐观了，完全不敢用来做决策参考。 |
| **日常使用工具** | SAS / Python（建模）、内部 BI 仪表盘、评分卡配置平台、Excel |
| **对 SpaceFin 的核心期望** | 一个**不会被美化偏见污染**的真实群体画像工具，让他能向产品/业务部门展示"这就是我们的借款人长什么样"。画像的聚合统计必须与内部真实分布一致。 |
| **采纳门槛** | 画像统计分布与真实数据的 KS 统计量 ≤ 0.05；画像可逐条审计追溯（为何生成这个画像、数据来源是什么）；能导出供监管检查的报告。 |
| **典型使用场景** | "我需要一份新市民借款人群体的合成画像，用于下季度的产品政策制定。画像要如实反映他们的债务收入比分布、收入稳定性、居住流动性，不要美化过的版本。" |

### 2.3 赵捷 · 贷后资产保全经理（用户）

| 维度 | 描述 |
|------|------|
| **基本信息** | 35 岁，贷后管理 / 资产保全经理，从业 7 年。法律 / 财务背景。 |
| **日常职责** | 监控逾期贷款、处置抵押物、与法务协同推进不良清收。管理 500-2,000 笔风险贷款。 |
| **核心工作流** | 接收逾期预警 → 判断处置优先级 → 安排评估师估值 → 制定清收方案 → 处置与回收 |
| **当前最大痛点** | **LTV 预警严重滞后**。抵押物估值只在放款时做一次，市场已经下跌 15%，但系统内 LTV 还是老的。等到触发预警时，处置窗口已经过了。同时每笔人工估值要等 3-7 天、花 ¥800-1,500，批量处置时成本很高。 |
| **日常使用工具** | 内部贷后管理系统、法院拍卖平台（查询参照价）、微信/邮件（沟通评估师） |
| **对 SpaceFin 的核心期望** | 全量存量贷款的**自动高频估值 + LTV 红灯预警**。但凡 LTV 超过 75% 的贷款自动弹出，不用等人工审查发现。 |
| **采纳门槛** | 估值更新频率至少每周一次；预警准确率 > 90%（降低误报）；与现有贷后系统可对接（API 或报表导入）。 |
| **典型使用场景** | "每天上班第一件事——看 LTV 红灯预警列表。标红的贷款要当天判断是否启动处置流程。" |

### 2.4 林琳 · 合规 / 审计专员（用户）

| 维度 | 描述 |
|------|------|
| **基本信息** | 40 岁，合规管理 / 内部审计，从业 12 年。法律 / 会计背景。 |
| **日常职责** | 审查风控流程合规性、准备监管报送材料、审计模型与算法的可解释性与公平性。 |
| **核心工作流** | 接收业务部门的技术方案 → 逐条对照合规清单 → 出具合规意见 → 跟踪整改 → 编写报送材料 |
| **当前最大痛点** | **算法黑箱无法溯源**。模型怎么算的、用了哪些数据、为什么给出某个评分——内部文档不完整，外部监管要求算法可解释，夹在中间很被动。尤其是当业务引入了外部工具/API 时，溯源更难。 |
| **日常使用工具** | 内部合规系统、监管公文系统（1104 报送）、Excel 检查清单 |
| **对 SpaceFin 的核心期望** | 能自动生成**可审计的决策链路报告**——"这笔估值是怎么算出来的、用了哪些数据字段、模型版本是什么、置信度多少"。要有审计日志，能按需导出。 |
| **采纳门槛** | 每条估值记录必须附带完整的溯源信息；报告格式满足 1104 报送要求；支持按时间段导出审计日志。 |
| **典型使用场景** | "审计发现有一批贷款的 LTV 在三季度末从 72% 跳到了 88%。我需要知道：是谁触发了重估、依据什么数据、模型版本是什么、置信度多少。" |

### 2.5 张总 · 金融机构管理层（间接用户）

| 维度 | 描述 |
|------|------|

| **日常职责** | 定战略方向、批预算、看结果。不直接操作系统，但决定是否采购。 |

| **日常使用工具** | 管理仪表盘、PPT 汇报、风控周报 |
| **对 SpaceFin 的核心期望** | 能回答"如果房价下跌 X%，我们的 LTV 分布会变成什么样、需要多少追加拨备"——一句话给出推演结论，而非打开一个系统慢慢查。 |
| **采纳门槛** | 汇报级可视化（打印到 PPT 上能用）；推演结论可在 1 页内讲清；年度预算 ≤ 50 万（城商行级别）。 |
| **典型使用场景** | "下周的董事会需要汇报——如果市场再跌 10%，我们的房贷组合整体 LTV 会到什么水平、哪些分行最危险。给我一个数字，不要一个项目计划。" |

## 3. 角色优先级矩阵

| 角色 | 在产品中的角色 | 核心诉求 | 对采购决策的影响力 | 优先级 |
|------|--------------|---------|------------------|-------|
| 信贷产品设计师 | 主用户 | 低成本策略推演 | 中（使用者，但不直接决策） | **P0** |
| 风控政策制定者 | 主用户 | 真实未粉饰的人群洞察 | 高（影响采购的技术评审） | **P0** |
| 贷后资产保全经理 | 用户 | 高频 LTV 预警 | 中（使用需求驱动采购） | **P0** |
| 合规/审计专员 | 用户 | 可审计可溯源 | 中（否决权，说不就不能用） | **P1** |
| 管理层 | 间接用户 | 压力测试与汇报 | 高（最终决策者） | **P1** |
