## 1. 验收环境与数据前提

- **报送数据源**：`ads_risk_class`（风险引擎写好的五级汇总）+ `dws_risk_class`（明细裁判）。本批次当前状态：五级 正常 136 / 关注 47 / 次级 6 / 可疑 6 / 损失 5，合计 200 笔 / **76,485,206.62**（与 AC-02 同批种子环境）。
- **三出口口径**（`reporting-1104.md` §3）：出口① `ads_risk_class`（stat_date=当日，内部累计）；出口② `dws_risk_class` 现状快照 SQL 聚合（独立复算裁判）；出口③ 1104 模板行（由出口①生成）。任一分级任一项不一致（笔数严格相等、余额差 ≤0.01、占比差 ≤0.0001）→ 记 mismatch → 写 `ads_report_alert`（level=block）→ **阻断报送**（exit 非 0、不写 `ads_1104_g11`）。
- **阻断演练钩子**：`--simulate-mismatch` 是组件自带的**内存级演练开关**（reporting-1104.md §5），只在内存里把 dws 聚合偏移 1 元再走完整校验，**不写任何业务表**——用它验证 AC-05 门禁不污染数据。
- **备注（环境修复）**：AC-01 实测期间，CDC 消费端（旧版 UTC 业务日期逻辑，见 cdc-downstream.md §4）曾把 +1000 快照写进 `ads_risk_class(stat_date=2026-08-05)`。为还原环境，测试后已按 `store.refresh_ads_risk_class` 同款 SQL 聚合语义，从 `dws_risk_class` 现状重算并**修复** 08-05 汇总行（当前与 08-06 行、dws 明细三方一致）。本次验收在修复后的干净态上执行。

## 2. 验收方法（独立执行路径）

**步骤**（运行环境 `~/miniforge/envs/spark/bin/python`，不依赖前端；直接调用报送 CLI）：

1. **正常路径取证（对照组）**：`python tools/reporting/main.py --date 2026-08-05` → 预期三出口一致、exit 0、`ads_1104_g11` 正常落库。
2. **不一致路径取证（AC-05 主证据）**：`python tools/reporting/main.py --date 2026-08-05 --simulate-mismatch` → 预期 exit 1、报告 `consistent=false/blocked=true`、mismatch 清单写进 `ads_report_alert`。
3. **告警留痕独立查证**：SQL 查 `spacefin_crawler.ads_report_alert` 最新记录，核对 `report_date/report_type/alert_level/check_name/detail`。
4. **阻断的落库边界查证**：确认阻断态下 `ads_1104_g11` 不被写入（阻断只落 blocked 态 CSV/JSON 供排查）。
