## 1. 验收环境与批次说明

- **合成种子**：`seed/generate_seed.py` 生成，广东 21 城 DWD 对齐版，200 笔贷款 / 200 笔抵押物 / 200 位客户（同 AC-02 批次）。
- **批次产物**：`python tools/risk/main.py --date 2026-08-05 --write-db`（全量重算 + 写 MySQL ADS），批次概览——总 200 笔，五级分类 正常 136 / 关注 47 / 次级 6 / 可疑 6 / 损失 5，`avm_hits=200`，`model_version=2026-08-05-r11`，`alerts_count=17`，`ltv_distribution.over_red_line=11`（LTV>0.85，含低置信口径），`low_confidence=10`。
- **两档预警口径**（与 PRD §6 / 测试用例 TC-03 一致）：`alert_level ∈ {strong, warn}`，LTV **严格大于** 强预警线 0.85 → `strong`；0.75 < LTV ≤ 0.85（严格大于警示线）→ `warn`；LTV 恰好 = 0.85 / 0.75 不触发对应档（B-01 等号边界）；**低置信（AC-04）抑制自动预警**。
- **预警落地**：`ads_ltv_alerts`（alert_date=2026-08-05，每日每笔一条，含 loan_balance / market_valuation / ltv / risk_class / is_high_risk_zone / alert_level）。

## 2. 验收方法（独立执行路径）

**独立重算脚本** `/tmp/ac0304_manual_check.py`（运行环境 `~/miniforge/envs/spark/bin/python`）：

1. **不读 DWS 结果**：仅从业务库 `spacefin`（loan.balance、collateral）与空间特征输入表 `spacefin_crawler.dws_spatial_feature` 读**原始输入**（后者是 L2 空间模块的输入侧产物，非风险引擎输出）。
2. **独立重算估值链**：复用 `tools/risk/valuation` 模块的估值函数（AVM 小区级 → DWD 行情 → true_market_price 兜底）逐笔独立重算 `market_valuation`。
3. **独立算 LTV**：`ltv = round(balance / valuation, 4)`。
4. **独立分档**：脚本内独立实现两档分档（严格大于比较，未调用引擎的分档函数），叠加「低置信抑制预警」。
5. **对比**：与引擎同批 `dws_risk_class`（MySQL，含 alert_level）逐笔比对 `alert_level`。

**边界专项** `/tmp/ac0304_boundary.py`：本批次无 LTV 恰好 = 0.85 的笔（见 §3），用生产函数 `risk_engine.enrich_loan` **构造压线输入**（balance=8,500,000 / 估值=10,000,000 得 LTV=0.8500 等）独立核对等号边界——不修改任何源代码与数据。

### 3.3 边界验证（B-01 等号边界）

### 3.4 T+1 推送（贷后保全接收，I-05）

- 引擎侧 17 条预警写入 `ads_ltv_alerts`（alert_date=2026-08-05）。
- 推送执行器 `tools/alerting/main.py --date 2026-08-05`：17 个候选全部送达站内告警表 `ads_alert_inbox`（dedup 4 + pushed 13），T+1 去重与失败重试状态机实测生效（13 条首次推送因目标表缺列失败 → 补列后重试成功）。推送明细含估值、余额、五级分类、高危区标注与 `alert_level`。
- ⚠️ **发现（不阻塞 AC-03）**：`ads_alert_inbox` 于 06:57 建表，早于 `alert_level` 列加入；`alerting.ensure_tables` 只 `CREATE TABLE IF NOT EXISTS`、不做存量表补列（对比 `risk.store.ensure_ads_tables` 的 `_ensure_columns` 幂等补列）。验收时手工 `ALTER TABLE ads_alert_inbox ADD COLUMN alert_level VARCHAR(8) DEFAULT NULL` 打通推送，建议开发将补列逻辑并入 alerting 建表流程（后续按审核意见修复）。

## 5. 结论

- **AC-03 验收通过**：LTV 两档预警等级（strong 11 / warn 6）在全量 200 笔上与独立重算完全一致；0.75 < LTV ≤ 0.85 归 `warn`、LTV > 0.85 归 `strong` 的分档语义落地。
- 等号边界（B-01）：批次内无恰好 = 0.85 / 0.75 的笔，由构造边界专项确认——**LTV 恰好 = 0.85 不触发 strong（只 warn）、恰好 = 0.75 不触发**，与引擎单元测试（`tests/test_enrich_loan.py`）一致。
- 预警记录带估值 / 余额 / 空间风险标注（risk_class、is_high_risk_zone）落库，T+1 推送路径经 alerting 模块实测送达。
- 旁证：`tools/risk/tests` 113 个测试全绿（含 B-01 等号边界、B-02 阈值可配置单测），`tools/alerting/tests` 47 个测试全绿。
