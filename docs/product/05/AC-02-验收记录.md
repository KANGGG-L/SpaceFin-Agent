## 2. 验收方法（独立执行路径）

**口径定义（与 PRD 一致）**：`risk_class` 由 `LTV = loan.balance / market_valuation` 按 `CLASS_LTV_UPPER` 分档——正常 ≤ 0.60 / 关注 ≤ 0.75 / 次级 ≤ 0.85 / 可疑 ≤ 1.00 / 其余损失；且 `collateral.is_high_risk_zone = 1` 时「正常/关注」至少升至「关注」。

**独立手工核对步骤**（一次性脚本 `/tmp/ac02_manual_check.py`，运行环境 `~/miniforge/envs/spark/bin/python`）：

1. **不读 DWS 结果**：仅从 MySQL `spacefin`（loan.balance、collateral 主档含 true_market_price）与 `spacefin_crawler`（DWD 行情、空间特征）读原始数据。
2. **独立重算估值链**：复用 `tools/risk/valuation` 模块的估值函数（AVM 小区级 → DWD 行情中位单价×面积 → true_market_price 兜底），逐笔独立重算 `market_valuation`——与引擎同源但独立执行路径，不引用批处理产物的估值字段。
3. **重算 LTV**：`ltv = round(balance / valuation, 4)`。
4. **独立分档**：脚本内**独立实现**五级分档逻辑（阈值取自 `config.CLASS_LTV_UPPER`，分档循环独立编写，未调用 `config.classify`），再叠加高危区提升规则。
5. **抽样**：随机抽 100 笔（种子 20260805）+ 分层补齐——全部高危区（is_high_risk_zone=1）与全部「次级及以上」（次级/可疑/损失）笔 + 贴近分类边界档位（|ltv − 任一阈值| ≤ 0.005）的笔，共补齐 23 笔，保证覆盖五个档位与边界。
6. **对比**：逐笔比对抽样 loan_id 的手工 risk_class 与 `dws_risk_class.csv` 对应行；另对全量 200 笔做参考性对照（不计入 AC-02 一致率）。
