## 2. 测试策略

- **分层**：单元测试（模型/算子）→ 集成测试（接口 I-01～06）→ 系统测试（闭环流程）→ 验收测试（AC-01～08）。
- **数据策略**：真实数据未接入前，以合成数据驱动全量用例（复用阶段 3 原型 schema）；Q1/Q2 落实后切换真实数据执行回归（R-rev-2）。
- **范围驱动**：以 PRD 验收标准 + EARS 需求 + 设计/研发评审点为唯一权威来源，不新增测试范围。
- **自动化优先**：湖仓分层、LTV 计算、1104 口径校验等可脚本化项优先自动化；UI 交互走手工 + 截图留痕。

## 5. 上线决策框架（Go / No-Go）

产品对每个问题进行三问判定，决定是否阻断上线：

| 判定维度 | 问题 | 处置 |
|---------|------|------|
| 是否阻断上线 | 缺陷是否使核心闭环（资产监控 / LTV 预警 / 1104 报送）不可用？ | 是 → P0，必须修复方可上线 |
| 是否影响核心流程 | 是否影响风控结论可信度或合规报送零差错？ | 是 → 关联护栏指标，限期修复 |
| 是否需调整需求范围 | 是否因技术/合规限制需缩减 MVP 范围？ | 是 → 回链阶段 3 PRD Non-goals，产品拍板 |

**Go/No-Go 出口**：验收清单全绿（或仅余 P2/P3 且经产品书面接受）+ 上线风险清单无新增 P0 + Q1/Q2 数据授权已落地 → 建议 Go。

## 7. 流程流转提醒

- **Bug → 事项**：发现的缺陷创建事项分配给开发同学，并关联回原需求 / PRD 文档（当前连接器未连接，需手动或通过已连接渠道）。
- **上传资料库**：验收结论、测试报告、上线风险清单建议沉淀为项目统一上下文。
- **添加关注人**：测试、研发、合规、风控策略经理应加入事项关注，确保缺陷状态及时触达。
- **决策提醒**：范围调整（是否缩减 MVP）须由产品负责人拍板，不替代负责人决策。
