## 2. 评审议题清单（Review Agenda）

### 2.1 设计评审议题（Design Review）

1. **页面与模块拆分**：是否覆盖 [用户故事 US-01～US-07](../03/README.md#3-用户故事user-stories) 与 5 角色 RBAC？是否有遗漏或冗余页面？
2. **关键状态机**：LTV 预警（正常/预警/低置信/异常估值）、1104 报送（待校验/校验中/已阻断/已报送）、AVM 估值（待重估/计算中/已完成/低置信/异常）的状态流转是否闭合、无悬空态？
3. **交互边界**：维度筛选 / 下钻 / 导出（PII 脱敏）/ T+1 刷新 / 降级策略是否在各页面一致落地？
4. **设计验收点**：可见性（权限隔离）、可审计（血缘/模型版本可见）、降级提示、一致性（跨出口数值一致）是否明确？
5. **沙盒推演页（P1）**：仅出交互框架与"未校准"标记规则，不进入本期开发排期。

### 2.2 研发评审议题（R&D Review）

1. **技术依赖图**：L0 湖仓为基座，L3 AVM、L2 Sedona、L5 合规分别挂接，L1（Flink CEP）本期仅做预警联动不闭环——依赖顺序是否成立？
2. **接口定义**：CDC/Binlog 接入、AVM 厂商 API、地图/POI API、Doris 倒排索引——契约、频率、失败处理是否明确？
3. **数据结构**：ODS/DWD/DWS/ADS 各层实体与字段（loan / collateral / spatial_feature）是否与原型 schema 对齐、能否支撑 1104 与 LTV 计算？
4. **兼容性**：部署环境（机构内网 vs 云）、浏览器、数据量级（亿级坐标）、与现有贷后/风控系统的对接方式？
5. **实现风险**：技术栈复杂度、MGWR 校准样本门槛、合规授权、算法备案——缓解措施是否可执行？

> 详细拆解见 [设计评审.md](设计评审.md) 与 [研发评审.md](研发评审.md)。

## 4. 关键依赖与风险

### 4.1 模块依赖（研发视角）

```
L0 湖仓底座(Hive+Doris) ────┬── L3 AVM(MGWR+GBDT) ──→ ADS 估值 ──→ LTV 预警
   │                        │
   ├────────────────────────┼── L2 空间(Sedona) ──→ 空间惩罚项 / 高危区
   │                        │
   └── L5 合规(倒排索引+1104) ──→ 报送校验 / 审计溯源
        （L1 Flink CEP：本期仅预警联动，不闭环）
```

**关键路径**：L0 必须先于 L3/L2 就绪；LTV 预警依赖 L3 估值产出；1104 报送依赖 L0 口径一致性。

### 4.2 风险登记（继承阶段 2 + 本阶段新增）

| # | 风险 | 等级 | 归属阶段 | 缓解措施 |
|---|------|------|---------|---------|
| R-tech-1 | 技术栈复杂（Doris+Sedona+Flink+多智能体），单人难端到端跑通 | 高 | 阶段 4→5 | MVP 先 L0+L3，Flink 仅做轻量联动；PoC 仅证核心链路 |
| R-tech-2 | MGWR 校准样本不足 → 带宽估计失真 | 中 | 阶段 5 | 限定样本量门槛；无成交小区降级人工 |
| R-tech-3 | 多智能体 ground truth 未定义 → 仿真黑盒（H3） | 高 | P1 沙盒 | Critic 强制对接真实不良率/普查基准，KS≤0.05 门禁 |
| R-cmp-1 | 数据源合规授权不到位（H5） | 高 | 阶段 4 | Q1/Q2 落实前不接入真实数据；数据源白名单 + 授权链路 |
| R-cmp-2 | 算法备案 / 可解释未达标 | 中 | 阶段 5 | 倒排索引 + 特征归因报告 + 定期偏见审计 |
| R-mkt-1 | 金融机构 POC→签约周期长 | 中 | 阶段 1/9 | AVM 单点切入，先做 1–2 家标杆 |
| **R-rev-1** | 设计稿与 PRD 验收标准漂移（如看板维度与 AC 不一致） | 中 | 阶段 4 | 设计验收点逐条回链 PRD AC-01～08（见 [设计评审](设计评审.md)） |
| **R-rev-2** | 真实数据未接入即进入研发，导致 schema 返工 | 高 | 阶段 4→5 | Q1/Q2 接洽与研发并行但分环境（合成数据先行，真实数据后切换） |
