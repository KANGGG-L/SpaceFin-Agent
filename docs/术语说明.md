# SpaceFin Agent 专业术语说明（Glossary / 术语表模板）

> **用途**：统一收录项目中的专业缩写与术语，降低跨角色（产品 / 研发 / 数据 / 合规 / 商务）沟通成本。
> **如何使用**：本文档本身即是「术语表模板」——新增术语时，**复制任意一个条目并按下方结构填写**即可。每条术语统一包含 5 个必填字段，便于快速查阅与机器解析。
> **维护**：术语随阶段推进持续增补；涉及数值口径变更的，同步更新「计算公式 / 量化方法」字段并注明版本。

## 条目结构说明（模板字段）

每个术语条目统一采用以下结构，顺序固定：

| 字段 | 说明 | 是否必填 |
|------|------|---------|
| **全称及中文译名** | 英文全称 + 中文译名（缩写首次出现时给出） | 必填 |
| **核心含义与业务背景** | 一句话定义 + 为什么这个项目/金融业务需要它 | 必填 |
| **影响数值的主要因素** | 列举会拉高/压低该指标的关键变量 | 必填（无影响因素填"不适用"） |
| **项目中的使用场景与操作方式** | 在 SpaceFin 哪个模块/流程被使用、如何操作 | 必填 |
| **计算公式 / 量化方法** | 精确公式或量化口径；不适用则写"不适用" | 按术语性质 |

## A. 风控与资产质量核心指标（项目核心）

### LTV — Loan-to-Value Ratio（贷款价值比）
- **核心含义与业务背景**：贷款余额与抵押物估值之比，衡量抵押物对贷款的覆盖程度。房地产下行周期中，放款时估值滞后会导致 LTV 系统性低估，是本项目"LTV 盲区"痛点的核心指标。
- **影响数值的主要因素**：抵押物市场价值下跌（↑LTV）、贷款余额不变、AVM 估值偏差、红线阈值设定（默认 0.85）。
- **项目中的使用场景与操作方式**：AVM 月度批次重估后自动计算；LTV > 红线时 T+1 推送贷后资产保全（PRD R-EVT-02）；贷后系统在预警列表查看处置建议。
- **计算公式 / 量化方法**：`LTV = 贷款余额 / AVM 估值`（逐笔计算，结果存 ADS 层）。

### NPL — Non-Performing Loan（不良贷款率）
- **核心含义与业务背景**：不良资产在总投放中的占比，监管与机构管理层最关注的资产质量"面子指标"。
- **影响数值的主要因素**：借款人还款能力、宏观经济、区域房价、五级分类口径。
- **项目中的使用场景与操作方式**：资产质量监控驾驶舱（T+1）展示；日终批处理按五级分类汇总（PRD R-STA-01）。
- **计算公式 / 量化方法**：`NPL = 不良余额 / 总贷款余额`（按五级分类汇总，DWS 层）。

### PD / LGD / EAD — Probability of Default / Loss Given Default / Exposure at Default（违约概率 / 违约损失率 / 违约暴露额）
- **核心含义与业务背景**：风控传统三要素。PD 借款人违约可能、LGD 违约后损失比例、EAD 违约时敞口。阶段 0 指出其"高度抽象、缺业务共鸣"，是本项目要升级的对象。
- **影响数值的主要因素**：客群特征、抵押物价值、宏观周期、产品参数。
- **项目中的使用场景与操作方式**：作为策略推演沙盒（P1）的输入基准；产品设计师据此理解群体风险。
- **计算公式 / 量化方法**：由评分卡 / 模型输出，本项目不重算，仅作为对照基准（不适用独立公式）。

### Roll Rate — 滚动率（迁徙率）
- **核心含义与业务背景**：贷款在不同逾期状态间迁徙的比例，用于预测不良演化。
- **影响数值的主要因素**：催收效率、宏观经济、区域风险。
- **项目中的使用场景与操作方式**：资产质量驾驶舱迁徙矩阵展示（PRD US-02）。
- **计算公式 / 量化方法**：`Roll Rate(30→60) = 30天逾期且在60天仍逾期笔数 / 30天逾期笔数`（窗口函数追踪状态跃迁，DWS 层）。

### 五级分类 — 贷款五级分类（正常/关注/次级/可疑/损失）
- **核心含义与业务背景**：监管要求的资产质量分类口径，是 NPL 与拨备的基础。
- **影响数值的主要因素**：逾期天数、担保覆盖、借款人还款记录。
- **项目中的使用场景与操作方式**：日终批处理重算并写入 DWS（PRD R-STA-01）；1104 G11 报送引用。
- **计算公式 / 量化方法**：按监管规则映射逾期/担保状态到五档（规则引擎，非单一公式）。

## B. 估值与模型算法

### AVM — Automated Valuation Model（自动估值模型）
- **核心含义与业务背景**：用数据驱动方法自动估算房产价值，替代人工评估（3–7 天/¥800–1500 → 分钟级）。本项目采用 MGWR+GBDT 混合架构。
- **影响数值的主要因素**：成交样本量、空间特征覆盖、小区活跃度、模型校准质量。
- **项目中的使用场景与操作方式**：月度批次重估全量抵押物（PRD R-STA-02）；结果写入 ADS 供 LTV 计算。
- **计算公式 / 量化方法**：MGWR 逐变量求解独立空间带宽 → 空间系数/滞后截距作衍生特征 → GBDT 捕获非线性交互（详见阶段 2 L3）。

### MGWR — Multiscale Geographically Weighted Regression（多尺度地理加权回归）
- **核心含义与业务背景**：允许每个自变量有独立空间带宽的回归方法，解决房地产"空间非平稳性"（全局 OLS 强制全城同系数会失真）。本项目估值核心算法。
- **影响数值的主要因素**：样本量（带宽估计需足够样本）、空间自相关强度、特征尺度差异。
- **项目中的使用场景与操作方式**：AVM 估值主模型；无成交小区降级人工（R-tech-2）。
- **计算公式 / 量化方法**：对每个自变量 k 迭代求解带宽 bw_k 与系数 β_k(u)，局部 R² 提升为验证指标（阶段 2 PoC 实证 R² +57.4pp）。

### GBDT — Gradient Boosting Decision Tree（梯度提升决策树）
- **核心含义与业务背景**：集成树模型，捕获特征间非线性交互；工业界估值/风控事实标准（XGBoost / LightGBM）。
- **影响数值的主要因素**：特征质量、树深度/迭代次数、过拟合控制。
- **项目中的使用场景与操作方式**：接收 MGWR 空间衍生特征，输出最终估值（阶段 2 L3）。
- **计算公式 / 量化方法**：加法模型 `F(x)=Σ_m γ_m h_m(x)`，梯度下降拟合残差（不适用手算公式）。

### MAPE — Mean Absolute Percentage Error（平均绝对百分比误差）
- **核心含义与业务背景**：AVM 精度度量，本项目 AVM 验收基线。
- **影响数值的主要因素**：样本分布偏移、外推小区、特征缺失。
- **项目中的使用场景与操作方式**：AVM 月度重估后统计全量 MAPE，验收门槛 ≤ 10%（AC-07）。
- **计算公式 / 量化方法**：`MAPE = (1/n) Σ |估值ᵢ - 成交价ᵢ| / 成交价ᵢ × 100%`。

### KS — Kolmogorov-Smirnov（KS 统计量）
- **核心含义与业务背景**：两分布差异度量；本项目用于验证"合成画像分布"与"真实不良率分布"是否同构（H3 生死假设）。
- **影响数值的主要因素**：合成数据生成质量、Critic ground truth 基准准确度。
- **项目中的使用场景与操作方式**：P1 沙盒校准门禁，KS ≤ 0.05 方可通过（阶段 3 R-OPT）。
- **计算公式 / 量化方法**：`KS = max_x |F_real(x) - F_synthetic(x)|`（两经验分布函数最大距离）。

### SHAP — SHapley Additive exPlanations（沙普利加性解释）
- **核心含义与业务背景**：模型可解释方法，满足金融 AI"可解释、可审计"护栏（阶段 2 L5）。
- **影响数值的主要因素**：模型结构、特征共线性。
- **项目中的使用场景与操作方式**：AVM / 空间惩罚项输出附特征归因报告（PRD §9 模型治理）。
- **计算公式 / 量化方法**：基于博弈论沙普利值分配特征边际贡献（不适用简式）。

## C. 空间计算与数据工程

### Sedona — Apache Sedona（分布式空间计算引擎）
- **核心含义与业务背景**：PySpark 生态的分布式空间计算库，解决"亿级坐标 × 万级多边形"Spatial Join 单机崩溃问题（阶段 2 L2）。
- **影响数值的主要因素**：数据量、集群规模、空间索引（R-Tree / S2）质量。
- **项目中的使用场景与操作方式**：住址 × 高危多边形相交、通勤/POI 距离计算。
- **计算公式 / 量化方法**：注入 Geometry / R-Tree 索引；ST_DistanceSphere（跨城大圆距）/ 平面距按尺度选用（不适用单一公式）。

### CDC — Change Data Capture（变更数据捕获）
- **核心含义与业务背景**：近实时捕获业务库变更，避免全量轮询对业务库的压力。
- **影响数值的主要因素**：Binlog 稳定性、网络、幂等设计。
- **项目中的使用场景与操作方式**：核心业务库发生信贷状态变更时，秒级同步至 ODS（PRD R-EVT-01，AC-01）。
- **计算公式 / 量化方法**：基于 Binlog 流，断点续传 + 幂等去重（不适用公式）。

### ODS / DWD / DWS / ADS — 数据仓库分层（贴源 / 明细 / 汇总 / 应用）
- **核心含义与业务背景**：湖仓一体（Hive 冷 + Doris 热）的分层架构，统一多源口径（阶段 2 L0）。
- **影响数值的主要因素**：ETL 调度、数据质量、口径定义一致性。
- **项目中的使用场景与操作方式**：ODS 贴源 → DWD 清洗关联 → DWS 汇总指标 → ADS 应用输出（看板/报送/预警）。
- **计算公式 / 量化方法**：分层流转为 ETL 管道，非单一公式（详见 `poc/data-foundation/avm_poc.py`）。

### 1104 G11 — 监管报送报表（资产质量报表）
- **核心含义与业务背景**：银保监非现场监管报表体系中的资产质量模板，合规报送刚需。
- **影响数值的主要因素**：口径一致性、数据授权。
- **项目中的使用场景与操作方式**：生成 ADS 层 G11 模板 + 口径一致性自动校验，不一致则阻断报送（PRD R-UBQ-02，AC-05/AC-08）。
- **计算公式 / 量化方法**：按 1104 监管模板字段映射，一致率 = 跨出口同指标一致数 / 总数（目标 100%）。

### PoC — Proof of Concept（概念验证）
- **核心含义与业务背景**：把"技术可行"从架构叙事变为可运行证据，降低工程风险（阶段 2 风险 R-tech-1）。
- **影响数值的主要因素**：范围界定、依赖控制。
- **项目中的使用场景与操作方式**：`poc/data-foundation/avm_poc.py`（H1 论证）、`poc/core-prototype/mvp_prototype.py`（端到端闭环）。
- **计算公式 / 量化方法**：不适用（交付物为可运行代码与结论）。

## D. 产品方法论与假设

### RICE — Reach / Impact / Confidence / Effort（覆盖 / 影响 / 信心 / 工作量）
- **核心含义与业务背景**：优先级量化框架，避免"拍脑袋排期"（阶段 1）。
- **影响数值的主要因素**：各维度打分的主观把握（Confidence）。
- **项目中的使用场景与操作方式**：阶段 1 对 10 项候选能力评分，RICE = R×I×C / E。
- **计算公式 / 量化方法**：`RICE = (R × I × C) / E`（R/I: 1–5，C: 0.2–1.0，E: 1–5）。

### MoSCoW — Must / Should / Could / Won't（必须有 / 应该有 / 可以有 / 这次不做）
- **核心含义与业务背景**：需求分类法，界定 MVP 边界（阶段 1）。
- **影响数值的主要因素**：战略判断、资源。
- **项目中的使用场景与操作方式**：MVP = F1(AVM)+F3(LTV预警)+F10(数据底座)；F5/F6/F7 归入 Won't（推迟）。
- **计算公式 / 量化方法**：不适用（分类框架）。

### EARS — Easy Approach to Requirements Syntax（需求语法简易法）
- **核心含义与业务背景**：无歧义需求描述法，五类：Ubiquitous / Event-driven / State-driven / Unwanted / Optional（阶段 3 PRD §4）。
- **影响数值的主要因素**：不适用。
- **项目中的使用场景与操作方式**：PRD 12 条需求按五类表述（R-UBQ/R-EVT/R-STA/R-UNW/R-OPT）。
- **计算公式 / 量化方法**：不适用（语法规范）。

### H1 / H3 / H5 — 核心假设（生死假设）
- **核心含义与业务背景**：阶段 0 的待证伪命题。H1 空间特征增量价值、H3 合成画像与真实分布同构、H5 数据合规可得；任一条证伪即调整方向。
- **影响数值的主要因素**：数据可得性、模型能力。
- **项目中的使用场景与操作方式**：H1 由 PoC 实证（R²+57.4pp）、H5 由数据摸底确认、H3 待 P1 真实分布验证。
- **计算公式 / 量化方法**：H1 验证 `R² 提升 ≥ 10pp`；H3 验证 `KS ≤ 0.05`；H5 为合规评估结论。

## E. 通用金融 / 业务缩写

### LTM — Last Twelve Months（过往十二个月 / 近十二个月）
- **核心含义与业务背景**：以当前时点往前推 12 个月的滚动窗口，用于消除季节性、呈现最新年化经营/风险表现。金融财报与风控复盘常用。
- **影响数值的主要因素**：单月异常波动被摊薄、业务季节性、近期趋势权重。
- **项目中的使用场景与操作方式**：可用于资产质量/逾期率的滚动窗口统计（如"近 12 个月 NPL 走势"）；当前 PRD 以 T+1 日终为主，LTM 多用于管理层驾驶舱（阶段 0 张总角色）的周期性汇报。
- **计算公式 / 量化方法**：`指标_LTM = Σ(最近 12 个自然月该指标)` 或滚动均值，视口径而定。

### GTM — Go-To-Market（市场进入 / 商业化策略）
- **核心含义与业务背景**：产品从研发到客户落地的商业化路径（渠道、定价、试点、签约）。对 ToB 金融机构尤指标杆行切入策略。
- **影响数值的主要因素**：试点行选择、定价模型（AUM/SaaS/调用量）、销售周期。
- **项目中的使用场景与操作方式**：商务侧推进（阶段 2 风险 R-mkt-1）；Q4 商业化定价模型待 P3 决策，本期不投入。
- **计算公式 / 量化方法**：不适用（策略框架）；定价可用 `SaaS 年费` / `AUM 计提比例` / `API 调用量计费` 等建模。

### MTM — Mark-to-Market（按市价计价 / 市值计价）
- **核心含义与业务背景**：以当前市场价格重估资产/负债价值，而非历史成本。房地产风控中即"用最新成交价重估抵押物"，正是本项目对抗 LTV 盲区的核心思想。
- **影响数值的主要因素**：市场流动性、最近成交可比性、估值频率。
- **项目中的使用场景与操作方式**：AVM 月度重估即 MTM 思想在抵押物上的落地；与"账面价值/放款估值"对比发现 LTV 背离（阶段 0 P1 案例）。
- **计算公式 / 量化方法**：`市值 = 最新可比成交价 × 调整系数`（AVM 即其工程化实现）。
