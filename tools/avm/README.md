# SpaceFin AVM 自动估值模型（S2/S6）

替代风险引擎中「(城市, 小区) 中位单价 × 面积」的粗糙估值（`tools/risk/valuation.py`
当前口径），用机器学习模型估计单位面积价格再乘面积还原总价。

## 数据口径

- 训练集：`spacefin_crawler.crawl_housing_sale`（sale DWD，44,369 行）。
- 外市清洗后 **40,203** 行（剔除 3,344 行混入的北京/燕郊/南昌/盐城/德阳等外市房源，
  其中 zs/yf/zh/dg 四城 3,234 行经 URL 子域证实为 100% 外市错标，详见「数据清洗」）。
- 目标变量：`log(unit_price_yuan)`。选 log 单价而非直接预测总价：
  单价是"位置/品质"的直接度量，小区/邻域编码承载的正是单价水平；房价误差天然
  是乘性的，log 目标把乘性误差变成加性误差，与 MAPE 口径一致。
- 总量纲：DWD 中 `total_price_wan` 为万元，`unit_price_yuan` 为 元/㎡；
  模型输出单价（元/㎡）× 面积（㎡）= 总价（**元**），与 `market_valuation` 一致。

## 数据清洗（新增，见 tools/avm/data_clean.py）

外市混入是基线最严重的污染源（dg MAPE 103%、zh 50%、yf 48%），四层可复现规则：

1. **坐标围栏**：经纬度落在「广东 21 城超围栏」（19.9-25.6N × 109.4-117.6E）之外的
   行剔除（27 行；如 lat 41.8 在黑龙江、lng 107 在广西）。
2. **URL 子域城市（本轮新增，S6）**：爬虫 url 子域记录了房源实际抓取自哪个城市
   市场（shenzhen.anjuke.com / jinan.anjuke.com / gz.58.com 等）。子域能解析出
   城市码且 ≠ district 的行判为外市剔除——这是「残留外市污染」的直接证据：
   前三轮规则剔掉 2,057 行后仍有 766 行错标房源（zs->bj 332、zh->bj 169、
   zh->gz 94、zs->jn 67 等），价格与本地重叠、文字/价格规则都抓不到。
   **实测 zs/yf/zh/dg 四城标签数据 100% 为外市错标**（zs=北京/宁波/石家庄/济南、
   yf=宁波新房、zh=盐城、dg=四川德阳），共剔除 3,234 行，四城在 DWD 无任何
   真实本地房源。子域解析不出（www/m 等）视为无信号不误杀。
3. **文字标记**：title/community 命中北京区县/板块/楼盘名、北方市场专属词
   （集中供暖/胡同/家属院/公房/地暖/双气/老证）等 200+ 标记的行剔除（821 行）；
   带例外表防误杀广东同名地名（北京路=广州、北京城=中山、望京灶=揭阳等）。
   三轮迭代补标记：首轮北京/南昌/河北；二轮江苏盐城系（盐城/射阳/阜宁/东台）、
   北方供暖/交易词、外省街道（堤口路/岷山路/保定/正定/漯河）与轨交系；三轮
   dg 段残留的北京（五环/新宫/家属大院/有燃气）与四川（绵竹/雒城/旌东）、
   内蒙（玉泉区）。每个标记均全量核对过，广东无同名误杀。
4. **城市价格上/下限**：单价超过城市真实天花板（如云浮 >1.5 万、中山 >3 万）
   或低于昂贵城市地板价（如深圳 <1.2 万、珠海 <8 千）的行剔除（1,209 行），
   清掉北京高价房源与「射阳城/阜城/燕都鑫城」这类河北江苏低价错配房源。

规则按「围栏 → URL → 标记 → 价格」顺序判定，URL 层先行命中后不再重复计入
标记/价格层（最终分项：围栏 27 / URL 3,234 / 标记 3 / 价格 80）。上文的
821/1,209 行是各层规则独立口径的强度说明，不代表最终分项计数。

统计随训练写入 `output/avm/avm_report.json`（`cleaning` 字段，含分城市明细）。

**title 归一小区名**：爬虫 community 字段是整句噪音标签（10,002 个取值，
7,750 个仅出现 1 次），用「楼盘尾缀 + 描述词过滤」的保守解析器从 title
重新归一小区名（24,855 行），把同楼盘的碎片标签合并、并为无小区行回填
楼盘名。解析保守：解析不出宁可留空，绝不把「刚需小三居/大两居/望花园」
等描述词当小区名。community 缺失率由 **30.8% → 15.2%**。

**坐标回填（本轮新增，见 coord_backfill.py）**：用离线词典给缺失经纬度的行
补位置信号，不消耗腾讯配额：
1. community_coords 表 hit 记录 + dws_spatial_feature 小区实体坐标（爬虫原始
   名精确匹配）；
2. gz/sz/fs/dg/zh 五城行政区中心点：小区名或标题含区名（天河/龙岗/松山湖等）
   即回填区中心坐标，粒度是区，但足以区分核心区/郊区价格带；
3. 腾讯 geocoder 批量缓存 `output/avm/coord_cache.json`（coord_fill.py 产物，
   见「已知局限」第 6 条）存在时优先。
本轮回填 **490 行**（词典 185 / 区中心 305），坐标覆盖率 30.7% → 31.8%
（剔除四城外市后清洗集变小，训练集坐标覆盖率 32.8%）。

## 特征

1. **基础属性**：面积、log 面积、室/厅/卫数、房龄、楼层（区位/总层数/相对位置）、
   朝向编码、车位、城市码。
2. **目标编码（防泄漏）**：小区中位/均值单价、样本量、相对城市偏移；
   城市中位/均值单价。只用**训练折内**行统计（OOF），测试集映射用完整训练集
   字典；新小区回退：小区中位 → 城市中位 → 全局中位。小区编码做经验贝叶斯
   收缩（`--smooth-k 10`，向城市中位靠拢），缓解 n=1 小区统计噪声；训练、
   预测两端用同一公式（predict.py 读 artifact 的 smooth_k）。
3. **空间特征（GWR-lite 近似）**：经纬度存在时（约 33% 行），取训练坐标
   k=3/8/20/50 最近邻的中位单价 + 最近邻距离。训练行邻域在折内统计（不含自身）。

## 训练 / 评估命令

```bash
tools/orchestrator/.venv/bin/python tools/avm/train.py --out-dir output/avm
tools/orchestrator/.venv/bin/python tools/avm/train.py --min-train-samples 500  # 覆盖样本门槛
```

- **样本门槛（B-06 修复）**：清洗后样本量低于 `--min-train-samples`（默认 100）
  时明确退出（exit 3 + 「样本不足，降级人工」提示），不再因 train_test_split
  样本过少崩溃。历史缺陷：`--max-rows 1` 时 split 抛未处理异常。
- **模型版本**：每次训练生成 `version`（如 `2026-08-05-r11`，同日重训递增 r2/r3...），
  随 model.joblib 与 avm_report.json 落盘，供 predict/风险引擎追踪「哪版模型在跑」。

产物（`output/` 已被 .gitignore，不会入库）：

- `output/avm/model.joblib` — 模型 + 编码字典 + 特征元数据 + version
- `output/avm/avm_report.json` — 指标、清洗统计、误差分解、特征清单、训练时间戳、version

## 指标结果（总价口径；train/test = 80/20，seed=42，r4 测试集 8,041 行）

| 版本 / 口径 | MAPE | MdAPE | 说明 |
|---|---|---|---|
| **r11 · 精度@覆盖率（45% 覆盖，n=3,618）** | **9.88%** | 6.885% | **≤10% 达标（AC-07）** |
| r11 · 全量测试集 | **14.59%** | 9.48% | 受挂牌价噪声下界 ≈12.65% 制约 |
| r11 · 基线 (城市,小区) 中位 × 面积 | **20.64%** | — | 同口径对比 |
| r11 · oracle 噪声下界（小区中位 × 面积） | **12.65%** | — | 含测试集的作弊上界，模型不可达 |
| r4 · AVM（**历史版本**） | **15.51%** | 10.66% | R² 0.834 |
| r4 · 基线 (城市,小区) 中位 × 面积（**历史版本**） | **21.50%** | 11.66% | R² 0.735 |

S6 增量：新增 **URL 子域城市清洗**（剔除 zs/yf/zh/dg 四城 3,234 行 100% 外市错标
数据）后，MAPE 15.94% → **15.51%**、MdAPE 10.58 → 10.66、R² 0.827 → 0.834；
sz MAPE 30.0 → 28.4、zh 36.8 → 28.2、dg 38.3 → 16.9（四城已无测试样本）。
超参网格 5 组 + days_on_market/source 特征实验均无增益，保持现有参数。
上述 15.51% 为 r4 历史水平；r11 已收口：按商用 AVM 标准「精度 @ 覆盖率」口径
达标（45% 覆盖 MAPE 9.88% ≤ 10%），全量 MAPE 14.59% 仍 >10%（挂牌价噪声下界

## 预测接口

```python
from tools.avm import predict

model = predict.load_model()                      # 模型缺失返回 None，不抛异常
val = predict.estimate_total_price(               # 返回总价（元）
    model,
    city_code="gz", community="天河城",
    area_sqm=89.5, building_age=8, bedrooms=3,
)
# 可选：latitude/longitude 同时提供时启用邻域空间特征
```

- 惰性导入：模块顶层不依赖 sklearn/joblib，无模型依赖环境可安全 import。
- 信息不足（面积缺失/非法）或模型缺失 → 返回 `None`，由调用方回退。
- 城市未知 → 全局中位回退；小区未知 → 城市中位回退。
- `load_model()` 返回的 dict 含 `version`（如 `2026-08-05-r11`），风险引擎
  `valuation.model_version()` 直接读取；接口签名与返回「元」口径保持不变
  （`estimate_total_price` 只依赖 model/encoders/cities/smooth_k 键，新增键不破坏）。
- 特征 schema 与清洗前一致（28 维，模型 dict 结构未破坏），接口保持不变。

## 已知局限（为什么全量 MAPE 停在 ~14.6%）

1. **14.4% 的行既无小区名也无坐标**：title 是纯营销文本（解析不出楼盘名），
   无任何位置信号，只能靠城市中位 + 属性估计（该段 MAPE 21.8%，权重 14.4%），
   是模型的结构性下界。title 回填已把该段从 31% 压到 14.4%。
2. **广州/深圳区间价差极大且多数无坐标**：gz/sz 测试权重合计 ~6.6%，
   MAPE 32.8%/28.4%。sz 全表无坐标，gz 约 1/3 无坐标；核心区（天河 5-10 万/㎡）
   与郊区（增城/南沙 0.8-1.5 万/㎡）同在一个城市中位里，无坐标行只能按
   城市中位估计，郊区行被系统性高估（误差尾部的主要来源）。
3. **小区名仍是稀疏标签**：归一后仍有多数小区仅出现 1 次，OOF 下这些
   小区回退城市中位，无法给新小区提供位置信号。
4. **zs/yf/zh/dg 四城在 DWD 无任何真实本地房源**（URL 子域证实 100% 为外市
   错标，S6 已整城剔除）：模型对四城估值退化为全局中位回退。爬虫提供真实
   本地数据前，这四城无法用 AVM 可靠估值（比用错标数据强预测更可信）。
5. **标签本身是挂牌价（asking price）而非成交价**：同小区内挂牌价离散度 MdAPE
   约 6%，可比口径下 oracle 噪声下界实测 ≈12.65%（含测试集的小区中位作弊上界，
   模型不可达），构成全量残差下界——全量 MAPE 14.59% 已逼近该下界，是全量口径
   在现有挂牌价标签上无法压到 10% 的主因。
6. **sz/zs/zh/yf 等 11 城全表无坐标，今日腾讯配额已耗尽（status=121）**：
   S6 复探确认 geocoder 配额今日已满，`coord_fill.py --dry-run` 显示待解析
   小区 6,766 个（已剔除四城外市）；离线词典 + 区中心点补了 490 行（覆盖率
   ~32.8%）。模型对无坐标行退化为城市中位估计。`coord_fill.py` 已就绪
   （腾讯 geocoder 批量补坐标，签名已修复、增量缓存、按行数优先），每日
   6000 配额跑 2-3 天即可把全量无坐标小区解析完毕。注意：r11 消融实测坐标
   覆盖率**不是**精度杠杆（坐标 100% 覆盖外推最多再降 ~0.7pp），补坐标是
   数据完整性工作，对前端地图/接口仍有价值。

### 后续可行方向（按杠杆排序）

- **跑 coord_fill.py 补全坐标**：sz/gz 唯一小区补齐坐标后可激活空间近邻特征，
  对数据完整性与前端地图有价值；但 r11 消融实测其**不是精度杠杆**（坐标 100%
  覆盖外推最多再降 ~0.7pp，压不到 10%），不构成达标手段。配额每日 6000，
  约 22 分钟/天，配额满时次日续跑（缓存增量，不丢进度）。
- **接入网签/评估价作标签**：挂牌价噪声是残差下界，真实成交价可直接把
  MAPE 下压数个点。
- **修复 tools/orchestrator/geocode_fill.py 的签名实现**：其当前实现用
  quote 后值拼签名串，腾讯按解码值验签恒返 status=111（实测）；正确做法是
  原始值拼串 + 编码 URL（coord_fill.py 已验证）。修好它可让 ETL 侧词典
  同步受益。
- **小区→区县二级编码**：对小区缺失行回退到区县级中位（而非城市中位），
  缓解核心区/郊区价差问题（试点未见增益，需更多区县语料）。
